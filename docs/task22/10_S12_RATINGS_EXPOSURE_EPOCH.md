# №22 — поправка из S12: EXPOSURE И НЕПРЕРЫВНОСТЬ РЕЙТИНГА

Источник продуктовых принципов: АН-01 14.11 (фактическое воспроизведение, partialExecution) и 18.11 (stable contentId/ratingEpoch и класс существенности правок), восстановленные выдержки S12. Основной документ: S-X-RATING-001 v0.3 §6: https://docs.google.com/document/d/1R8-ikXeQnSPTMXc-TLOwPFbE7k35SFeTbu7juCigTzM/edit . Данный файл приоритетнее формулировок 01_MAIN_TASK/03_ACCEPTANCE, которые могли ошибочно приравнивать рейтинг к contentRevision.

1. Рейтинги программы, модуля и трека на публичной карточке сохраняются по stable logical contentId + current ratingEpochId. Technical contentRevision, actual SessionRun manifest, track/module occurrences и timestamps сохраняются на каждом source feedback event для аналитики, но новая revision не является новой публичной оценочной сущностью.
2. Любое изменение названия/метаданных, пауз, порядка, параметров воспроизведения и даже слышимого аудио или замены/добавления/удаления трека НЕ сбрасывает рейтинг parent program/module, НЕ создаёт ratingEpoch автоматически. Новый отдельный trackId — собственный рейтинг; старый trackId сохраняет историю. Ручной новый ratingEpoch с audit/owner permissions — неутверждённый управляющий UX, не реализовать скрытый автоматический reset.
3. Косвенный сигнал из общей оценки программы распространять ТОЛЬКО на фактически проигранные component occurrences: NOT_EXPOSED — нет сигнала; PARTIAL — отдельно помеченный ослабленный signal (вес OPEN); COMPLETED — полный context signal. Playback telemetry ≠ доказательство внимания слушателя. При UNKNOWN не предполагать completion.
4. Прямая оценка программы при partialExecution остаётся самостоятельным субъективным отзывом и помечается partial; не распространять отзыв на неначавшиеся треки. Повторы module/track occurrence документировать, но не умножать один отзыв на независимые голоса. Дедуп повторных сессий требует отдельной политики/owner approval.
5. ProgramDirectRating != moduleDirectRating != trackDirectRating != indirectContext. F031 добровольна, local-only by default; серверный opt-in/withdraw корректирует агрегаты. Никаких выдуманных числовых весов.

Контроль: A completed/B partial/C not-exposed; повтор того же трека дважды; редакция программы после замены трека; ratingEpoch не сменился; новый trackId пустой, старый рейтинг trackA не достался trackB; авторский revision breakdown сохранён.
