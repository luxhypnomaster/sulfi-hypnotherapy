# БЕЗОПАСНОСТЬ, ГРАНИЦЫ И ЧТО НЕ ДЕЛАТЬ

- Запрещено менять/перезапускать live Google Apps Script, scope/permissions/OAuth, Google Drive ACL, production endpoints, платежи, юридически чувствительные авторские/клиентские базы, коммерческую систему Alchemica, новые скины/голоса K-028. Живой сервер — следующий отдельный цикл после принятия №15.
- Никакого arbitrary hardcoded shortcut API, demo серверной кнопки без работающего provider, фиктивного `published=true` когда backend не настроен.
- Прежняя авторская APK должна обновляться поверх установленной (не менять applicationId/signature/versionCode без необходимого безопасного решения). Не делать uninstall/reset/drop данных и не выдавать archive→restore за безопасное тестирование с реальной личной базой. Перед обновлением — внешняя полная резервная капсула.
- Сохранить утверждённый экран активной сессии K-024/K-026/K-027 без изменений: кобра/колба/огненные часы/таймер, фуксия активных, зелёный завершённых, жёлтые длительности. Не перебрать UI заново.
- No wholesale refactor: использовать действующие `CapsuleService`, `LocalCatalogSource`, `RevisionKey`, `DiaryEntry` и `SULFI_EDITION=client`; сначала базовый audit, потом точечное исправление.
- Новые HTML/JS UI или внешние зависимости только при действительной потребности, с pinning и тестами; не включать секреты в репозиторий, лог или скриншоты.
- Клиентский build не должен скрыто иметь авторские endpoint capabilities; локальный mode switch не должен подменять серверную аутентификацию.
- Миграция на синтетической заполненной БД; если права/данные/дизайн неясны — не делать инвазивную догадку, фиксировать blocker. Безопасный PARTIAL предпочтительнее недоказанного PASS.
- Ссылки на исходные отчёты и точные K/F ID в source map, не переносить старые `current` в статус без новой проверки.
