# ТЗ №15 — ЧТО ПОЛУЧАЕТ ВЛАДЕЛЕЦ

**Цель:** одна крупная, но контролируемая спецификация, после которой можно перейти к подключению сервера и проверке «Автор на одном телефоне → Клиент на другом». Это не серверный запуск; Codex должен вернуть работающий локальный комплект и контракт.

## Результат по порядку
1. У одного и того же библиотечного модуля, два экземпляра в сессии: изменён только A → жёлтая метка «(Изменено)» и фуксия+курсив только у A; B и новый C обычные. Убрали изменения → пометка исчезла. Имена модулей не переименовываются.
2. Щит «Автор/Клиент» сверху справа на главной, библиотечный щит оставлен, они показывают одно и то же состояние.
3. Выбранный экспорт на телефон = `Sulfi_exp_Imya_modulya_DD.MM.YY.zip`, а не «резервная копия»; внутри оригинальное имя и полная структура. На странице библиотеки виден реальный пункт импорта ZIP; его выбор запускает локальную установку без Android «Извлечь». Full backup отдельно.
4. Звуковые ревизии и файлы после обновления не ломают старую историю и личные данные; если Codex не может доказать сохранность, обязан объявить блокер.
5. Дневник офлайн: запись/категории/приоритет/read/reannounce/expiry и ContentLink; публикация на реальный сервер ещё не включена.
6. Два test APK/режима из одной кодовой базы (Автор и Клиент) с коннектором FakeProvider; готовый проверяемый контракт для сервера.

## Перед обновлением APK
Создай внешнюю полную резервную капсулу и проверь, что она лежит вне приложения. Обновляй существующую авторскую APK поверх прежней, НЕ удаляя данные. Для проверки нового клиентского издания лучше использовать отдельный телефон. Android может отличать build-time client edition от локального переключателя роли.

## Что НЕ считается доказательством
Зелёный unit/widget тест не доказывает живой сервер, физический звук и перенос с одного настоящего телефона на другой. Серверное соединение и облачная публикация — **следующее ТЗ**. Если функция непроверена, статус PARTIAL или NOT RUN.
