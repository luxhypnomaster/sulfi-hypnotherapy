# ПРОДОЛЖЕНИЕ CODEX ПОСЛЕ ЛИМИТА

1. ВОЗВРАЩАТЬСЯ В ТУ ЖЕ ЗАДАЧУ Codex / cloud environment и СУЩЕСТВУЮЩУЮ ветку, если она ещё доступна; новые независимые выполнения не получают несохранённое состояние автоматически. Прежде возобновления проверить `git status`, `git log -8`, `PROGRESS.md`, checkpoint commits, current CI/PR.
2. Читать не весь ТЗ повторно, а `PROGRESS.md` и инструкцию ближайшего Gate в `TASK_RU.md`; сохранить истину по уже закрытым acceptance IDs. Проверить незавершённый filesystem/SQLite operation и не повторять небезопасный импорт без состояния.
3. Команда продолжения: «Продолжай ТЗ №15 с последнего завершённого checkpoint/коммита; сначала сверь Git и PROGRESS.md. Не повторяй пройденные Gate и уже проверенные тесты без причины. Исполняй следующий незавершённый Gate, после него сохрани отдельный коммит, тесты и обнови PROGRESS.md. При риске данных остановись с диагностикой».
4. `PROGRESS.md` обязательно после каждого Gate: schema `gate; before_sha; after_sha; PASS_IDs; PARTIAL_IDs; open blockers; touched tables/files; last test command+result; exact next step`. Указывать текущий этап ещё до дорогого запуска.
5. Тесты: targeted после каждого Gate, полный suite после risk migration и в конце; CI после стабильного HEAD. Не запускать несколько агентных копий этой задачи одновременно, чтобы не переписывать общую ветку.
6. Если cloud environment недоступна после длительного простоя: восстановить **только запушенные коммиты** и отчёт о последнем checkpoint, не заявлять, что незапушенные изменения пережили удаление окружения. Дальше адресно восстановить незавершённый Gate, не стартовать с G0 полностью.
