# ДНЕВНИК + ДВА РЕЖИМА + СЕТЕВАЯ ПОДГОТОВКА (БЕЗ LIVE SERVER)

## Подлинные согласованные решения
См. разделы 7–12 архитектуры дневника и K-001…K-011, K-018/K-022/K-023. Не заменять принятые категории произвольными. Сохранять существующий локальный редактор упорядоченных text/image/audio blocks, private drafts и реальный voice player.

### Шесть базовых категорий (предмет, не признак срочности)
- Развлечения
- Таро
- Объявления
- Запись на приём
- Критические обновления приложения
- Новые модули и шаблоны

«Материалы о гипнозе» и «Другое» исторически предлагались, но не были утверждены как часть закрытой шестёрки. Для корректных нераспознанных categoryId предусмотреть безопасный fallback, не повреждая запись.

### Read-state
- Изображения/text: только после последней реальной страницы. Audio: только после действительного окончания, не после открытия записи и не после ручного seek-to-end, если этот путь не приводит к реально завершённому воспроизведению. Смешанная запись: обе части.
- Прочитано по `reader identity + entryId + activationCycleId`, локально на устройстве. Нельзя хранить viewer read в общедоступном author manifest.
- Частичное прочтение и пауза сохраняют прогресс; перелистывание назад, повтор открытия, смена темы/категории/тишина в плеере не выставляет read. Не использовать runtime позицию предыдущей сессии автоматически в новой редакции.

### Автор / публикация
- `draft/revision` независимы от `publicationStatus/activationCycleId`. Тихая правка не возвращает прочитанную запись в unread. Явная «Показать снова как новое» изменяет cycle и возвращает в ротацию. Не дублировать entryId/бинарные байты.
- Visibility manual, until timestamp, combined: эффективная видимость = `published AND not authorClosed AND now < validUntil(if defined)`. Использовать UTC contract, не локальную строку. Закрытое остается в авторском архиве/может быть активировано снова.
- Витрина Home: новая актуальная непрочитанная приоритетна; далее чередование «приоритетная→обычная→приоритетная» с детерминированной стратегией fairness. Прочитанные не показываются и остаются в ленте-архиве. Когда новых нет — исходная заставка Сульфи. Конкретное media-layout главной K-008 ещё не утверждено; запрещено создавать новый стиль вместо существующей рамки.
- Превью автора в дневнике и на главной: реальный существующий widget, фиксирован один текущий черновик, rotationDisabled и no-side-effects, ничего не публикуется и не меняет read-state. Если медиавид главной недоступен без нового утверждённого дизайна, отметить UI-blocker и не изображать готовый preview.

### Инкрементальная публикация (для будущего сервера)
Manifest/index и медиа по отдельным immutable asset SHA. Diff на уровне блоков/контента: title/category/priority/порядок→binary uploads=0; новая картинка→1 новый blob; тихая правка→без read reset; реанонс→новый cycle/0 binary uploads; старые версии и references удерживать. Описать `DiffPlan` и проверить mock recorder без реальных HTTP/OAuth.

### Роль клиента
- Переключатель shield в авторском APK является UX mode; он не выдаёт привилегии. Отдельная клиентская тестовая сборка из той же кодовой базы через имеющийся `SULFI_EDITION=client`; не хранит администраторские токены и не содержит авторский secret путь. Hidden UI и client edition не являются доказательством безопасности — будущий сервер должен проверять пользователя/роль на каждом write/asset endpoint.
- Client edition сохраняет session/audio/library/history и reader diary, не имеет author publication/editor controls. Тестировать локальными заранее созданными fixture публикациями и FakeProvider, без live сервера/оплаты. Обновления обоих editions через CI без изменения подписанного авторского package ID.
- Для второго телефона поддержать выпуск отдельного тестового клиентского APK через существующий GitHub workflow. Возможность отдельного applicationId проверять по действующему Gradle/flutter config; не делать несовместимый update авторского APK и не утверждать физический монтаж без evidence.
