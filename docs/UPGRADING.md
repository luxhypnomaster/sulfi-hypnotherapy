# Обновление и сохранность данных

Миграция SQLite 1 → 2 проверяется автоматическим тестом на настоящей старой схеме: сохраняются строки аудио, ID, категории, относительные имена и сами файлы. При запуске после совместимого обновления приложение автоматически добавляет новые поля/таблицы.

У Android есть отдельное условие обновления: **одинаковые applicationId и ключ подписи**. ApplicationId `ru.sulfi.sulfi_hypnotherapy` не изменён. Постоянный подписывающий ключ пока не настроен. Debug APK, собранные на разных временных GitHub runners, могут иметь разные ключи. Поэтому новый APK из Actions может быть отклонён при установке поверх предыдущего. Успешная миграция базы сама по себе не решает вопрос подписи.

**Не удаляйте установленное приложение для обхода ошибки подписи, если там есть нужные файлы/данные.** Удаление уничтожает его приватное хранилище. Тестовый APK можно проверить на отдельном устройстве/эмуляторе. План постоянной подписи и переноса существующих данных требует отдельного согласования владельца; в этой итерации ключи не менялись и удаление приложения не выполнялось.

Для владельца доступен способ сохранить содержимое старой debug-установки через USB/ADB перед любыми будущими действиями миграции. Команды выполняются на его компьютере; архив содержит личные данные и не должен отправляться в GitHub:

```sh
adb devices
adb exec-out run-as ru.sulfi.sulfi_hypnotherapy tar -cf - files > sulfi-private-backup.tar
```

Затем нужно локально проверить, что архив читается и содержит `files/library.sqlite` и `files/audio/`. Во время копирования приложение должно быть остановлено, чтобы получить согласованные файлы БД. Этот шаг только создаёт копию; **он не является готовым автоматическим переносом или зашифрованным экспортом**. Если `run-as` не разрешён или приложение хранит данные в другом каталоге, остановиться и уточнить способ сохранения, не удалять приложение.

Перед официальными обновлениями нужны постоянный надёжно сохранённый ключ, проверка установки поверх существующей версии и резервное копирование. Для отката — новый исправленный APK с увеличенным versionCode, а не обещание установки более старой версии поверх новой. Git и APK не заменяют личный бэкап.
