# СУЛЬФИ — САМОГИПНОЗ
## ЕДИНАЯ ФУНКЦИОНАЛЬНАЯ СПЕЦИФИКАЦИЯ V4.0 — СОГЛАСОВАННОЕ СОСТОЯНИЕ НА 03.11.2026

**Статус:** основной нормативный документ для Codex. Исправляет и заменяет v2, v3.0 и v3.1, включая противоречивые указания в прежних пакетах. **Работать с существующим Flutter-проектом, не создавать приложение заново.** Макеты — визуальные референсы, не готовые экраны и не заменители нативной разметки. # 1. УТВЕРЖДЁННАЯ ТЕРМИНОЛОГИЯ

### Единственная пользовательская иерархия — «Фаза → Модуль → Трек»

- **Фаза** — крупный смысловой участок сессии: «Подготовка», «Индукция», «Проработка» и проч. Это **тип этапа** и его конкретные экземпляры в сессии. Фазы одного типа **могут повторяться** и перемещаться. Нумерация в сеансе — порядковая, тип фазы имеет постоянный ID. Один сеанс может содержать несколько проработок.
- **Модуль** — именованная переиспользуемая техника или набор элементов, например «Индукция Элмана» из трёх MP3 или «Серая комната». Определение модуля живёт в **каталоге модулей**, применение в сессии — его редактируемая **копия**. Один и тот же модуль **можно добавить несколько раз внутри одной фазы** и в разных фазах, без особой команды «Дублировать модуль»: повтор выполняется обычной кнопкой **«Добавить модуль»**.
- **Трек** — отдельный аудиофайл, импортированный либо записанный, и отдельное его использование в сценарии. Дорожки одного аудиофайла можно воспроизводить неоднократно с собственными паузами, выключать, переставлять, переносить между модулями/фазами.
- **Интервал** — воспроизводимый по времени, но без MP3 элемент: «Тишина» или «Самостоятельная работа». Отдельно учитывать время задержки **перед** любым элементом, в том числе первым.
- **Теги** — слово для поиска аудиофайлов, не «метки». «Категория библиотеки» и «тип фазы» — разные поля, не путать.

Слова **«блок», «раздел», «аудиоблок», «выбрать аудиовыход»** в пользовательской структуре заменить по смыслу, НЕ слепым переименованием сущностей в БД. Для общего количества: `4 трека · 2 интервала`, а не `6 блоков`; фазы и модули считать отдельно. В пользовательской команде записи говорить **«Записать свой трек»**, поскольку одна запись — трек, а не модуль.

**Модельная оговорка:** внутри фазы допустим отдельный вручную добавленный трек/интервал без обязательного создания модуля; это исключение для гибкости, не четвёртый уровень. В UI он отображается как «Отдельный трек» внутри фазы. Нельзя заставлять пользователя создавать именованный модуль ради одного трека.

# 2. КАТАЛОГ ФАЗ И ПРАВИЛА ИХ ПРИМЕНЕНИЯ

| Стандартный порядок | Тип фазы | Назначение |
|---|---|---|
| 1 | Подготовка | Общие инструкции, запрос, как использовать приложение/паузы, правила остановки |
| 2 | Индукция | Вход в гипнотическое состояние, различные варианты индукции |
| 3 | Углубление | Техники углубления и фиксации внимания |
| 4 | Безопасное место | Формирование воображаемого опорного пространства |
| 5 | Проработка | Исследование чувства и различные необязательные техники |
| 6 | Возвращение в безопасное место | Возвращение к опорному пространству и стабилизация |
| 7 | Интеграция | Осмысление и закрепление опыта |
| 8 | Прогрессия | Мысленная репетиция будущих действий |
| 9 | Установки | Авторские или личные тематические записи |
| 10 | Выход | Завершающая аудиопоследовательность и ориентация в настоящем |

Это **справочник десяти стандартных типов**, а не десять обязанных проигрываться элементов. При создании пустого пользовательского шаблона редактор показывает все десять доступных типовых фаз в рекомендованном порядке; пустые, невключённые — компактные строки без длительности. На главной — только активные наполненные фазы. Фаза включается/выключается без потери её содержимого. Не создавать ненужных автоматических треков в пустых фазах.

`Добавить фазу` — явная видимая кнопка вне общего меню `⋮`. Выбор типа может создать новый `PhaseInstance` даже при уже имеющемся таком типе. Новому экземпляру допустима подпись «Проработка — запрос 2». Фазы перемещаются, отключаются и удаляются с подтверждением, если есть введённые данные. Стандартные `PhaseType` не удаляются из каталога.

**«Серая комната» — опциональный МОДУЛЬ фазы «Проработка»**, не самостоятельная одиннадцатая типовая фаза. При этом через выбор всех модулей она может применяться и в иной фазе по решению автора. Никакого автоматического включения интенсивных техник.

**Важно:** идея стартового шаблона «Разведка» методически обсуждалась, но **его сейчас НЕ собирать, НЕ включать в APK и НЕ создавать фиктивные MP3/заглушки как будто они доступны**. Текущая стадия — подготовка механизма и ручное наполнение треками. Шаблоны «Разведка», «Курение», «Вес» и т. д. — задачи дальнейшей отдельной итерации после появления записей. В «Подготовке» в будущем разместятся инструкции; в этом PR не генерировать их содержание и озвучку.

# 3. КАТАЛОГ МОДУЛЕЙ, ВКЛЮЧЕНИЕ В ФАЗУ, ЦИКЛЫ

**Каталог модулей нужно уметь наполнять пользователю уже в этой версии.** Старое указание v3.1 «модули только с обновлениями, пользователь не создаёт» отменено. Существующий каталог из обновлений и локальные пользовательские модули сосуществуют; модуль может быть пустым в момент создания и заполняться по мере импорта треков.

Минимальная карточка `ModuleDefinition`: стабильный ID, название, описание, необязательные теги, рекомендуемые `PhaseTypeId[]` (0 или несколько, только для выдачи первым в списке), упорядоченный состав треков и при необходимости интервалов, версия, источник (`localUser` / `bundledFuture`), время изменения. Для будущих встроенных авторских модулей данные версионируемые. **Сегодня** они появляются как обычные локальные записи пользователя.

### Создание и редактирование каталога модулей

1. При добавлении или записи аудиотрека можно выбрать: **«Добавить в существующий модуль»**, **«Создать новый модуль»**, либо **«Оставить только в библиотеке»**. Третье необходимо для файлов, которые ещё не распределены. Сохранённый трек существует независимо от модулей.
2. В существующий модуль добавление трека — отдельная явная операция над **каталогом**; модуль получает новый элемент в конце состава (или в выбранную пользователем позицию, если UI позволяет). Создание нового модуля запрашивает название и при необходимости краткое описание, затем включает туда трек. В одной категории MP3 могут быть элементы разных модулей и без модуля.
3. Редактирование состава/очерёдности/удаление **ссылок на треки из локального определения модуля** должно быть доступно в управлении модулями или редакторе карточки модуля. Это не удаление самого аудиофайла.
4. Удаление модуля из каталога предупреждает о связанных шаблонах, черновике и истории. Не стирать используемые аудиофайлы. При возможности мягкое удаление/архивирование определения и сохранение снимков в сценариях.
5. **Не привязывать заранее жёстко `Фаза → Модуль → Трек`:** пока библиотека не наполнена, рекомендуемые связи пустые или частично заполненные. Пользователь свободно выбирает любой модуль из каталога для любой фазы. Рекомендуемая принадлежность — фильтр/первый список, а не запрет.

### Внутри конкретной фазы

- Раскрытая фаза показывает подходящие модули, отмечая доступность, включённость и наличие несохранённых/локальных изменений; отдельная вкладка/кнопка **«Все модули»** даёт выбрать **любой** модуль независимо от рекомендаций. Если у фазы нет рекомендуемых модулей, показывать приглашение выбрать из всего каталога, а не пустой тупик.
- Нажатие `Добавить модуль` создаёт новый **ModuleInstance** с собственной копией состава и настроек из `ModuleDefinition`, не изменяя оригинал. Повторное открытие и переключение фазы НЕ создаёт вторую копию само по себе. Но повторный сознательный выбор **того же модуля в этой же фазе допустим** — новый ID и независимые треки/паузы. **Специальную кнопку «Дублировать модуль» не делать.**
- Один модуль можно выключать и включать, сохраняя его пользовательские изменения; `Вернуть исходный состав модуля` должно быть отдельным подтверждаемым действием, если применено. При индивидуальной правке — признак `Изменён`.
- При выборе альтернативы существующему модулю явно предложить **«Заменить»** (с предупреждением о потере текущих настроек) или **«Добавить ещё один»**. Не включать обе индукции неожиданно из-за просмотра альтернативы.
- Свободный трек из всей библиотеки, включая «Мои», можно добавить в фазу напрямую либо в выбранный модуль. Из любого типа и любой категории. Можно добавить один файл несколько раз, сделать разную паузу перед каждым и разные местоположения.
- Время выполнения определяется **единым видимым порядком** модулей и отдельных треков/интервалов; внутри модуля — свой порядок. Любая перестановка должна совпадать с реальным исполнением, не только менять картинку. Модуль всегда может содержать 1 или больше треков/интервалов; пустой модуль не влияет на длительность.
- При правке **экземпляра** модуля внутри сессии НЕ перезаписывать его **определение** в каталоге. При правке определения каталога НЕ менять автоматически уже созданные экземпляры в сохранённых шаблонах или истории. Можно предложить отдельную команду «Обновить экземпляр из каталога», но это не обязательная функция MVP.

**Пример циклов:** `Подготовка → Индукция → Безопасное место → Проработка (модуль X, модуль Y, модуль X повторно) → Возвращение в безопасное место → Проработка (новая фаза, другие модули) → Интеграция → Выход`. Никаких автоматических ограничений уникальности по `phaseTypeId`, `moduleDefinitionId` и `audioAssetId`; уникальны только ID экземпляров.

# 4. БИБЛИОТЕКА АУДИО И ИМПОРТ

Три верхних библиотечных раздела (не фазы): **«Общие аудиозаписи», «Установки», «Мои аудиозаписи»**. Подкатегории, поиск по названию/описанию/тегам, фильтрация, предварительное прослушивание, редактирование метаданных, а также просмотр модулей, в которые включён трек. Наличие 200+ файлов не должно ломать экран.

**Форма MP3:** исходный формат и длительность считываются из файла; `Название трека`, `Раздел библиотеки`, `Категория`, `Описание`, **`Теги`** (ввод через запятую или чипы), `Добавить в модуль` с выбором нового/существующего/без привязки. Подпись «Метки через запятую» заменить на «Теги», поле можно пояснить плейсхолдером «Например: Элман, погружение». Категория библиотеки не диктует, где трек применим в сессии.

Импортировать реальные локальные MP3/M4A/WAV, если поддерживаются существующим декодером; при необходимости честно сообщать о несовместимом формате. Выбранный файл скопировать в управляемое приложением локальное хранилище/устойчивое URI; не полагаться на одноразовое разрешение file picker. Не разрушать метаданные при повторном импортировании, не создавать дубликаты без выбора пользователя. По возможности вычислять длительность до сохранения.

Переименование `AudioAsset` не меняет метаданные ранее запущенного `SessionRun`. Удаление файла, на который ссылаются модули, шаблоны, черновик или история, должно показывать последствия и требовать подтверждения; запрет на молчаливое удаление. Сохранённые треки, пользовательские голосовые записи и файлы в истории локальны, без автоматической синхронизации.

Далее в обновлениях могут поставляться bundled audio и авторские готовые модули. Для этого подготовить стабильные идентификаторы/версию и поддержку `source=imported|recorded|bundled`, но сейчас **не завозить магазин, paywall, контент-фиктивы и хардкод реальных аудиофайлов**.

# 5. ДИКТОФОН «ЗАПИСЬ ТРЕКА» — ОДОБРЕННЫЙ ЭКРАН И РЕАЛЬНЫЙ ФУНКЦИОНАЛ

**Реализацию диктофона считать обязательной задачей: сейчас он отсутствует/не работает по наблюдению автора.** Основной визуальный референс: `assets/screens/02_RECORDER_APPROVED.png`. Он утверждён **после** перестановки секций и кнопок и замены микрофона на фирменную спираль. **Не заменять макет другим и не менять местами нижние кнопки.** Детальный автомат состояний и приёмочные тесты в `04_RECORDER_STATE_MACHINE_RU.md`.

Композиция **сверху вниз**:
1. Исходный портрет Сульфи/неоновый заголовок `Запись трека`, слева заметная **розовая спираль** вместо значка микрофона (спираль также центральный акцент записи). Рядом узнаваемая золотая перьевая ручка у кожаного планшета (тонкая, чёрно-золотая, аккуратная, без уродливого карандаша).
2. На **верхней части кожаного планшета** — `Параметры трека`: обязательное название, описание, категория библиотеки, теги и управление добавлением в существующий/новый модуль или без связи. Длительность фактической записи определяется таймером, не требует ручного выбора.
3. **Ниже параметров, непосредственно над финальными кнопками** — большая зона `Запись`: фирменная спираль как центральная кнопка начала/продолжения, индикатор уровня/волны, таймер, чёткий текст статуса. Под нею четыре действия **«Удалить», «Воспроизвести», «Пауза», «Завершить»**. Не надо постоянно показывать четыре активные функции, когда они не применимы — кнопки должны иметь корректное состояние (доступна/неактивна/переименована).
4. Внизу доступны большие `Отмена` **слева** и **`Сохранить трек` справа** (ярко-зелёная). Расположение рассчитано на работу большим пальцем внизу телефона.

**Ключевой UX-контракт:**
- Начальная спираль запускает запись только **после разрешения пользователя на микрофон**; первое касание при отказе даёт понятный запрос/сообщение, а не молчаливую имитацию записи. Центральная спираль при паузе продолжает запись. В активном состоянии изменение волны и индикатор `● Идёт запись` должны соответствовать реальному доступу к микрофону.
- `Пауза` — только при записи, останавливает запись звука без уничтожения файла; `Продолжить` — после паузы (можно через центральную спираль). Таймер длительности **аудио** не растёт во время паузы.
- `Завершить` — прекращает запись и формирует доступный для предпрослушивания временный файл; **не сохраняет его автоматически в библиотеку**.
- `Воспроизвести` — только после завершения или в режиме паузы при технически доступном безопасном предпрослушивании; управление play/pause preview и позиция, без нового звукового захвата. Предпочтительный простой MVP: прослушивание готовой записи после `Завершить`.
- `Удалить` — удаляет **несохранённый дубль** с подтверждением, очищает состояние и даёт возможность записать заново. Не удаляет ранее сохранённый трек из библиотеки без отдельной процедуры.
- `Сохранить трек` — активна после успешного завершения и непустой записи, при наличии названия и корректной выбранной привязки. Создаёт один `AudioAsset` (source=`recorded`), файл в контролируемом хранилище и, **если явно выбрано**, ссылку на трек в существующем/новом `ModuleDefinition`. Двойное нажатие не создаёт два файла. При возврате в редактор фазы можно отдельно вставить его как `TrackOccurrence` в текущий экземпляр модуля/фазы.
- `Отмена` или системный Back при несохранённой записи требуют подтверждения потери; без записи возвращают сразу. Редактирование полей разрешено до сохранения, при необходимости скрывать клавиатуру, чтобы запись/сохранение оставались достижимыми.
- Корректно обрабатывать отказ в разрешении, занятый микрофон, отсутствие места, неожиданную остановку, прерывания аудиофокусом, идущий фоновый сеанс (не инициировать параллельно чувствительную запись молча). Предпочтительный MVP — не записывать микрофон одновременно с воспроизводимой гипносессией; предложить сначала остановить/приостановить соответствующий режим.
- Запись в библиотеку НЕ создаёт `SessionRun` и не присваивает номер будущей сессии. По умолчанию имя `Личная запись · Вт, 03.11.2026 · 01:14` при отсутствии пользовательского названия; его можно изменить. Вызов из модуля должен знать контекст возврата, но не автоматически менять существующий исходный шаблон.

**Не смешивать три назначения:** личный библиотечный трек (входит в MVP); голосовая заметка к черновику; запись речи **во время исполнения интервала** в SessionRun. Последние два в нынешнем задании — только архитектурно предусмотреть; **не обещать уже работающую фоновую запись речи** до отдельной реализации/проверки. При любой записи пользователя всегда нужно явное действие, а не скрытый старт.

# 6. ШАБЛОН, ТЕКУЩИЙ ЧЕРНОВИК И ПРОВЕДЁННАЯ СЕССИЯ

**Три независимые сущности:** `SessionTemplate` (многоразовая исходная конфигурация), `CurrentSessionDraft` (единственный автосохраняемый на устройстве текущий рабочий вариант), `SessionRun` (неизменяемый снимок на момент старта + фактический журнал исполнения).

Первый запуск при пустой библиотеке показывает пустой редактируемый черновик/возможность создать свой шаблон и сообщение, что необходим импорт аудиозаписей. **Не устанавливать фиктивную «Разведку» как действующий шаблон.** При последующих открытиях возвращать последний черновик. Изменения в черновике не переписывают базовый шаблон; показывать `Изменён`. Изменение исходного модуля в каталоге также не должно молча менять ранее сохранённый шаблон.

Текущая дата и текущее время — информационные, номер сессии до старта лишь **предварительный**. Только нажатие `Начать трансформацию` создаёт настоящую запись истории и атомарно назначает номер/время. Отменённый до запуска редактор истории не создаёт.

Экран «Шаблоны» умеет: создать новый пустой, показать/поискать, выбрать (копирование в черновик), копировать, переименовать, удалить с подтверждением, создать из текущей конфигурации. `Вернуть из шаблона`, `Сохранить как шаблон`, `Применить и вернуться` — разные операции. Перезапись существующего шаблона только явным подтверждаемым действием. При переключении с изменённого черновика предупредить о замене и предложить сохранить, продолжить без сохранения как шаблон или отменить. Физическое автосохранение черновика сохраняется независимо от выбранной операции.

**Не создавать конкретные платные и бесплатные лечебные программы сейчас.** Архитектурное поле `contentPackId` допустимо на перспективу, но не оплачивать, не блокировать и не продавать внутри APK. Авторские шаблоны будут сформированы позднее, когда появятся нужные записи.

# 7. ГЛАВНЫЙ ЭКРАН — ОДОБРЕННЫЙ СТИЛЬ, ИСПРАВЛЕННАЯ КОМПОНОВКА

**Главный визуальный референс:** `assets/screens/01_MAIN_APPROVED.png`. Он одобрен автором как композиция и характер: сексуально-дерзкий портрет Сульфи с янтарными глазами и очками, фуксия/лайм, готическая кожаная тетрадь/планшет с золотым зажимом и аккуратной перьевой ручкой, яркая призывная зона, фирменная художественная спираль. **Не откатывать стиль в серую минималистичную форму и не менять лицо персонажа.** Дизайн не является статической подложкой для всей логики.

Нужен редактируемый ввод темы и доступ к заметке; макет иллюстрирует компактную свернутую тему, но **не должен лишать возможности редактирования**. День недели обязателен. Вертикально прокручиваемая область на 20–30+ треков. Иерархия фазы/модули/треки с возможностью компактного сворачивания; на главной **только активные наполненные фазы**, пустые в редакторе доступны. Название трека 1–2 строки, никакой `Самостоятельна...` из-за узкой колонки. Видны пауза **до** записи, длительность, краткое описание, ссылки в редактор.

В утверждённом художественном макете эта карточка могла быть сокращена, но **функционально ранее утверждена и не должна исчезнуть**. Разместить компактно, сохранив главную область структуры.
5. Большая кислотно-зелёная кнопка строго **`НАЧАТЬ ТРАНСФОРМАЦИЮ`** (последнее окончательно утверждённое название; старое `Начать сессию` заменить в публичном UI). Она запускает конкретную сессию, а не отдельную маркетинговую страницу. Внутри базы и системном уведомлении термин «сессия» сохранять, не обещать гарантированный результат.
6. После реализации проверенного фонового режима — спокойная короткая подсказка `Можно заблокировать экран — аудио продолжит воспроизводиться`; до реальной проверки не утверждать это как успешно работающее.
7. **Ровно четыре нижние кнопки** в этом порядке: **`Записаться к мастеру`** (фирменная розовая спираль, рукописная подпись, может быть в две строки), **`Библиотека`** (наушники), **`Шаблоны`**, **`История`**. На главной **НЕТ** «Записать» и микрофона. Первая кнопка не обязана визуально повторять три другие, допустима дерзкая асимметрия как в утверждённом макете; но выдержать реальные размеры экрана, touch target и системные отступы.

**Спираль:** последняя утверждённая художественная спираль более вихревая, чем ранняя геометрическая. **Не менять последний одобренный макет из-за прежних дискуссий о строгой спирали**. Пакет содержит как готовые ресурсы, так и художественный референс; если фактическая иконка Flutter/launcher в ресурсах отличается от большой спирали на мокапе, не утверждать, что это точное совпадение. Для разработки использовать приложенный ресурс и сохранять единый визуальный характер; отдельное переутверждение логотипа не требуется для этой функциональной итерации.

**Важнее красоты:** имена, дата, фазы, тайминги и доступность действий должны быть читаемы на узком телефоне, при шрифте 120–150%, корректно работать с экранной клавиатурой. Не хардкодить фоновую иллюстрацию с текстом вместо Flutter-виджетов.

# 8. ПОЛНОЭКРАННЫЙ РЕДАКТОР «СТРУКТУРА СЕССИИ»

Отдельный экран технического планшета без большого портрета. По сравнению со старым скриншотом `assets/current/STRUCTURE_OLD.jpg`:
- Верхний статус: имя активного шаблона/черновика, `Изменён` и реальный расчёт `N фаз · M модулей · K треков · J интервалов`, аудио/паузы/работа/итого. Никаких неверных «блоков».
- В редакторе **все десять стандартных фаз доступны**; активированные экземпляры могут повторяться и иметь собственное положение. Пустые фазы свёрнуты и компактны. Чекбоксы/переключатели включают/выключают конкретный `PhaseInstance` без уничтожения настроек.
- В раскрытой фазе: рекомендуемые/доступные модули с переключателями, каталог «Все модули», независимые экземпляры модулей, их треки и отдельные треки/интервалы. При выборе модуля добавляется весь его базовый состав, но каждую дорожку можно отдельно выключить, передвинуть, повторить, удалить из экземпляра и настроить паузу. Повторное добавление того же модуля в той же фазе разрешено.
- **Видимые кнопки** `Добавить фазу`, `Добавить модуль`, `Добавить трек`, `Добавить интервал`, `Добавить из библиотеки`, `Записать свой трек`. Не прятать создание/управление фазой за `⋮`.
- Нижние действия, которые сохраняем: `Выбрать другой шаблон`, `Библиотека`, `Записать свой трек`, `Вернуть из шаблона`, `Сохранить как шаблон`, `Применить и вернуться`. Можно композиционно адаптировать под маленький экран, но не терять работающие операции. `Применить` **не запускает** сессию.
- Перетаскивание фаз, модулей, треков, интервалов; пункт меню `Выбрать аудиовыход` **удалить** как концептуально ошибочный. Ввод в Android системный аудиовыход определяется системой: наушники/динамик/Bluetooth. **Фаза `Выход`** — содержательная завершающая техника, не аппаратное устройство.
- Технические операции удаления должны подтверждаться, если удаляются изменённые пользовательские элементы. Отмена/Back не должна внезапно стирать текущий черновик. Применённые изменения автосохраняются.

В будущем автор может включать готовые программы, но **в этой версии нельзя предполагать наличие авторских MP3, которых ещё нет**.

# 9. ПАУЗЫ, ТИШИНА И РЕДАКТОР ЗОЛОТЫХ ЧАСОВ

На любом исполняемом элементе есть `delayBeforeMs` — **пауза ДО** него, включая первый. Отдельный `Silence`/`FreeWork` — самостоятельный элемент длительности. Не заменять задержку до трека «периодом после трека»; не терять её при перемещении элемента. Для паузы перед первым треком человек может подготовиться и лечь с погасшим экраном.

Полноэкранный золотой таймер (`assets/screens/03_PAUSE_CLOCK_REFERENCE.png`): круглые золотые карманные часы, **крышка открыта вниз**, в центре глаз, два **независимых** боковых регулируемых диска — минуты (шаг 1 мин) и секунды (шаг 5 сек) с тактильной обратной связью, плюс ручной ввод. `MM:SS`, контекст «перед каким треком/интервалом», фаза/модуль, длительность следующего трека, текущая длительность фазы, предварительная новая длительность всей сессии и дельта. Никакого двойного подсчёта заменяемой паузы.

Кнопки: `Обнулить`, `Прослушать предыдущий трек`, `Прослушать следующий трек`, `Применить`; снизу рабочий мини-плеер с названием/описанием, прогрессом, seek и play/pause. `Обнулить` только для редактируемого значения, `Применить` меняет текущий черновик; до нажатия — предпросмотр. Мини-плеер не начинает сессию и не создаёт историю. Предыдущий/следующий трек — ближайший в **итоговой реальной последовательности**, без заголовков и тишины.

Общая длительность = фактически включённые аудиодлительности + активные delays + длительности интервалов. При открытой/нефиксированной свободной работе обозначать оценку, а не ложную точную сумму.

# 10. ИСПОЛНЕНИЕ СЕССИИ: ПОНЯТНЫЕ УПРАВЛЕНИЕ И СТАТУСЫ

**Сейчас экран реальной сессии, по наблюдению автора, запутан. Перед изменением изучить его текущие действия**, убрать дублирующие/ложные кнопки, привести к следующему явному контракту. Действующий плеер НЕ заменять статичной красивой панелью.

Кнопка `НАЧАТЬ ТРАНСФОРМАЦИЮ` на главной:
- Проверяет, что хотя бы один исполняемый элемент присутствует, нужные аудиофайлы доступны/разрешены. Если библиотека ещё пустая — **не имитировать сессию**; показать, что надо импортировать записи/собрать структуру. Отдельная полностью «тихая» сессия из интервалов допускается только по явному выбору, если её поддерживает движок.
- Создаёт один `SessionRun` с номером, локальной датой, днём недели (вычисляемым), временем и временной зоной старта, полным замороженным планом и начальным статусом. Переключает на экран выполнения.
- Исполняет строго `пауза перед первым → первый элемент → пауза перед вторым → второй → ...`; если промежуток добавлен через `Silence/FreeWork`, его время считается один раз.

### Экран выполнения — не больше необходимого

**Постоянная часть:** тема, номер, фаза/модуль, название и тип текущего элемента, elapsed/remaining (или оценка), прогресс, реальный статус `Воспроизводится / Пауза / Тишина / Самостоятельная работа / Завершена / Прервана`, возможность открыть подробности. Следующий элемент показывать ненавязчиво. Выдержать тёмно-неоновую стилистику, но крупные очевидные элементы управления.

**Всегда доступная основная кнопка:** `Пауза` или `Продолжить` (одно место, взаимоисключающие состояния), действует одновременно на воспроизведение, отсчёт пауз и интервалы. На экране блокировки поддерживается нативным MediaSession.

**Контекстные действия только для `FreeWork`:** `+5 мин` / `Продлить работу` и `Завершить работу` (завершает **этот интервал**, переходит по плану дальше). Не показывать как общесессионные `Завершить сессию`.

**Отдельные действия прекращения:** `Перейти к выходу` — попытка перейти к первой доступной настроенной последовательности из фазы `Выход`, пропуская оставшееся; если такой аудиодорожки нет, показать честный резервный вариант текстовой ориентации/остановки **без фиктивного проигрывания**. `Прервать сессию` — прекращает сейчас, с подтверждением, сохраняет статус `Прервана`. В UI не размещать рядом две одинаково оформленные кнопки `Прервать` и `Завершить`, смысл которых непонятен. Можно вынести опасное действие в меню подтверждения, а `К выходу` оставить различимо доступным.

**Завершение штатно** — когда закончилось всё расписание: `Завершена`. **Досрочный переход к выходу** — `Завершена досрочно с выходом` (или поддерживаемый эквивалент) и список реально пропущенных элементов, не отмечать всё как проигранное. **Сбой/вынужденное прерывание** — `Ошибка / Прервана`, не выдавать за успешную сессию. Состояния должны иметь полную схему переходов в `03_DATA_MIGRATION_IMPLEMENTATION_RU.md`.

Журналировать реальные события: запуск, пауза, продолжение, начало/конец трека, начало/конец интервала, продление, досрочное завершение, выход, отмену, исключение, окончание; записать actual timestamps и playhead. Текущие изменения во время исполнения не меняют шаблон и исторический frozenPlan. По возможности периодически сохранять checkpoint, а также на каждом важном переходе.

**Безопасность:** выходной модуль не должен превращаться в обязательный автоматический запуск интенсивного аудио при сбое. При отсутствии завершающих MP3 в меню показать «Завершающий трек не настроен» и предложить остановку и простую ориентацию в настоящем. Не заставлять человека проходить регрессию или иную технику, если он хочет остановиться.

# 11. ФОН И ЗАБЛОКИРОВАННЫЙ ЭКРАН — ОБЯЗАТЕЛЬНО

Приложение воспроизводит **всё расписание**, а не только MP3, при сворачивании, отключении экрана и блокировке телефона. На Android это должен обеспечивать корректный `foreground media service` + `MediaSession` (в Flutter рассмотреть `audio_service` и `just_audio`, **сверив фактические зависимости проекта**; не навязывать неподдерживаемые версии). Сценарий должен жить в сервисе/отделённом state-machine, а не UI `Timer` в виджете.

- Экрану можно гаснуть; **не держать экран включённым** и не советовать оставлять приложение перед глазами, если реализация подтверждена.
- Короткие и длинные интервалы тишины/работы продолжают идти в фоне; если OS убила процесс, не объявлять успешный исход; после перезапуска — чекпоинт и возможность корректно восстановить/прервать. Нельзя обещать неуязвимость к force-stop от пользователя.
- Android notification/lockscreen controls реально переключают паузу и продолжение в состоянии очереди; в момент тишины сервис не должен уничтожать свою медиасессию так, чтобы следующий трек не начался. Состояние сети не должно влиять на локальный сеанс.
- Корректно обрабатывать звонки, loss/gain audio focus, Bluetooth, проводные наушники, отключение гарнитуры. При потере гарнитуры **поставить чувствительное аудио на паузу**, а не неожиданно включать динамик. Аппаратный маршрут звука выбирает Android, отдельного «Выбрать аудиовыход» в редакторе **нет**.
- Выключение экрана/переход в другое приложение не создают новых `SessionRun` и не сбрасывают elapsed/remaining.
- После реального теста заменить предупреждение про необходимость держать открытым на `Можно заблокировать экран — сессия продолжится`. Если не протестировано или система не поддержала — сообщить честно в отчёте.

**Проверить на реальном Android (в т. ч. Samsung):** сессия из MP3 → пауза 30–120 сек → следующий MP3, продолжительные интервалы 5–15 минут, lock/unlock, background, энергосбережение, Bluetooth, телефонный звонок. Не писать «проверено» на основании одного `flutter test`.

# 12. ИСТОРИЯ — КОМПАКТНЫЙ ЖУРНАЛ, ПОВТОР, НОВЫЙ ШАБЛОН

История создаётся **только по факту запуска**. Новые сверху. В свернутом виде **две читаемые строки, обычно 65–85dp по высоте**: `№ + день недели, дата, время`, далее `статус + фактическая длительность + короткая тема`. Не показывать огромную карточку с повторяющейся датой, полными заметками и большими пустыми отступами (см. `assets/current/HISTORY_OLD_EXPANDED.jpg`). На больших шрифтах высота может закономерно увеличиваться.

По нажатию — подробности и фактический журнал выполнения: план и реальные события, полные заметки и время, завершение/прерывание, фактически сыгранные/пропущенные элементы. Доступны действия **`Повторить сессию`** (загрузить полную замороженную конфигурацию в `CurrentSessionDraft`, вернуться на главную без автозапуска, не переносить старый номер/дату/status; тему можно скопировать редактируемо) и **`Создать шаблон из сессии`** (создать отдельный `SessionTemplate` по **всему плану на старте**, даже при прерывании, не менять текущий черновик). Заметка отдельным действием. История сама по себе не удаляет аудиофайлы.

**Время:** хранить UTC timestamp и original timezone/offset. Показывать дату **и день недели** по исходной локальной дате сессии, включая историю, подробности и связанные сессией записи; день недели рассчитывать, а не сохранять «вторник» как неизменяемую строку без даты. Переезд между часовыми поясами не должен превращать прошлую сессию с понедельника во вторник. В главной текущий день/часы обновляются автоматически.

Если когда-то удалён аудиофайл: история сохраняет название/длительность из замороженного плана, повторение/создание шаблона сообщает об отсутствующем файле. Не подставлять другие записи без разрешения и не выдавать неполную структуру за идентичную прежней.

# 13. СВЯЗЬ С МАСТЕРОМ И НИЖНЯЯ НАВИГАЦИЯ

**Публичная подпись утверждена окончательно: `Записаться к мастеру`**. Не `К мастеру`, не `Записаться` и не скучное отдельное `Записаться на приём`. Подпись может быть в две строки/рукописном стиле, первая нижняя кнопка со спиралью. Экран над кнопкой не перекрывать дополнительной записью поверх портрета. Главная кнопка `НАЧАТЬ ТРАНСФОРМАЦИЮ` — другое действие.

По нажатию на первую кнопку открывать **компактное модальное окно выбора канала связи**. Пункты:
1. `Telegram` — настроенный HTTPS/t.me адрес контакта или бота, куда действительно можно написать, **не обязательно ссылка на канал скачивания APK**. Открывать внешним приложением/браузером.
2. `Электронная почта` — `mailto:` с темой `Запись на консультацию`; при отсутствии обработчика показать адрес и кнопку `Скопировать`.

`bookingTelegramUrl`, `bookingEmail`, `bookingEnabled`, `bookingButtonLabel` хранить в одном конфигурационном месте, редактируемом при сборке APK. Если контакт не настроен, не предлагать сломанную кнопку; если оба отсутствуют, показывать ясную недоступность/скрывать CTA. **Не выдумывать Telegram-бота или адрес email.** В будущем список можно расширить другими провайдерами, но сейчас строго два способа. Не делать встроенный чат, форму с личными данными и backend.

Никакая информация из сессий, аудио, темы и заметок не передаётся в Telegram/email автоматически: пользователь лишь выбирает внешний канал. IMO/WhatsApp/VK не добавлять в данном релизе.

# 14. ИКОНКА ANDROID, СПИРАЛЬ И ВИЗУАЛЬНЫЕ РЕСУРСЫ

В пакете `assets/spiral/` лежат реальные графические файлы PNG/SVG из прежнего утверждения: адаптивная иконка Android foreground/background, monochrome, legacy, прозрачная UI-спираль и примеры навигации. **Это ресурсы, а не просто картинка с ТЗ.** Не передавать Codex указание «изобрази новую спираль на свой вкус».

Android launcher icon: **фирменная розовая гипнотическая спираль на тёмном фоне, БЕЗ букв/подписи внутри**, Android под ней сам выводит название приложения `Сульфи`. Для маленьких размеров и themed icons использовать специальные варианты, с правильными adaptive icon safe zones. Полное бренд-название внутри приложения: «Сульфи — Самогипноз» (в шапке допустимо стилизованное Sulfi/Сульфи согласно последнему макету).

Рисунок в утвердившемся макете более динамичный/вихревой, чем ранние векторные ассеты. **Решение по текущему макету: оставить художественную спираль как есть**. Готовые ранние файлы применять для текущей функциональной сборки без ложного утверждения их точной идентичности новой художественной спирали; если внешне конфликтуют — отметить как визуальное расхождение, но не делать несанкционированный редизайн. Для диктофона — розовая спираль **вместо символа микрофона в верхней области** и как центральная кнопка записи. Для нижней записи к мастеру — спираль и рукописное `Записаться к мастеру`.

Портрет Сульфи не перекрывать, фоновое оформление сохранять, ручку сделать аккуратной чёрно-золотой перьевой. Все input, кнопки, таймеры должны быть настоящими Flutter-виджетами, поддерживать accessibility и доступность, а не зашитыми внутрь фоновой иллюстрации.

# 15. МИГРАЦИЯ И ПОРЯДОК РАЗРАБОТКИ

До первой правки Codex изучает структуру текущего Flutter-репозитория, зависимости, локальную БД/файлы, все сохранённые шаблоны и предыдущие тесты. Создаёт резервные/тестовые фикстуры старых форматов, сохраняет файловые ссылки и идентификаторы, проводит idempotent schema migration. Старые «блоки» переводятся в `TimelineItem` без потери реальной аудиодлительности, задержек и порядка; старые элементы без фаз сохраняются в явной совместимой/временной фазе, не пропадают.

Вместо одной монолитной попытки начать с модели/миграции, далее модули/импорт, экраны, диктофон, history/run, background, UI polish. После каждого этапа — компилируемое приложение и тесты, PR в `develop` из feature-ветки, `main` не менять. Если в проекте совсем другая структура, не переименовывать названия классов вслепую; адаптировать модели к сохранению поведения.

Подробная логическая схема и миграционный контракт — `03_DATA_MIGRATION_IMPLEMENTATION_RU.md`, recorder state machine — `04_RECORDER_STATE_MACHINE_RU.md`, сценарии тестирования — `05_ACCEPTANCE_TESTS_RU.md`.

# 16. ОГРАНИЧЕНИЯ И ЧЕСТНОСТЬ РЕЗУЛЬТАТА

- Пока нет озвученных авторских модулей — **не придумывать** MP3, готовые курсы, фиктивные шаблоны «Разведка», «Отказ от курения» и прочие обещания.
- Профессиональный конструктор доступен в MVP, продажи шаблонов, лицензии, подписки и locked templates **позже**.
- В приложении можно остановить/прервать работу, не принуждать к дальнейшему погружению; не обещать гарантированного психологического эффекта. Интенсивные техники, в том числе серая комната, необязательны. Воображаемые сцены не подтверждают подлинность прошлых событий.
- Локальные записи пользователя не отправлять наружу автоматически. Отдельное согласие/разрешение на микрофон обязательно.
- Не заявлять, что Android background воспроизведение или диктофон работают, если реально не реализованы и не проверены. Для real-device тестов требуется пользовательский телефон/оборудование.
- **Чисто художественные надписи на изображении не имеют приоритета над этой спецификацией**: пример «4 фазы · 4 модуля · 6 треков» не означает реальные числа; UI считает данные. Референс не обязывает добавлять те MP3, которых нет.

**Критерий приемки:** полный перечень тестов в `05_ACCEPTANCE_TESTS_RU.md`; сдача включает код, миграцию, анализ/тесты, APK при доступном Android SDK и русскоязычный отчёт о реально сделанном и о не проверенном.
