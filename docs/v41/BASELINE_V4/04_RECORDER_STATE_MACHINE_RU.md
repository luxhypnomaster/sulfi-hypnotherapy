# Сульфи v4.0 — ДИКТОФОН: ДИЗАЙН, СОСТОЯНИЯ, КНОПКИ

**Единственный утверждённый визуальный референс:** `assets/screens/02_RECORDER_APPROVED.png`. **Не возвращаться** к раннему варианту, где запись была выше метаданных, «Сохранить» слева, а вместо ручки был карандаш. Не возвращать микрофон вместо спирали в верхнем заголовке.

## 1. Вертикальная иерархия

1. Портрет, бренд, заголовок «Запись трека», сверху слева розовая **спираль** вместо пиктограммы микрофона.
2. Верхняя половина планшета — **Параметры трека**: «Название трека*», «Описание», «Категория», «Теги» (chips или запятые), «Добавить в модуль» (существующий / создать новый / без привязки). Для записанного трека начальная категория верхнего уровня — «Мои аудиозаписи»; подкатегория может быть «Индукция» и т. д. Длительность измеряет диктофон, она не ручной выбор `00:30` по умолчанию.
3. Нижняя половина планшета — **Запись**: большая спираль как главный круглый орган управления, с уровнем голоса/волной и таймером. Для слабого устройства анимация волны может быть облегчённой, но не должна имитировать наличие сигнала, когда захват остановлен.
4. Под волной **четыре места под действия** слева направо: `Удалить`, `Воспроизвести`, `Пауза/Продолжить`, `Завершить`. Это **одна группа**, не отдельный второй «Сохранить». При недоступности действия оно визуально disabled, и всё равно понятно, когда будет доступно.
5. Низ: **Отмена слева**, **Сохранить трек справа**, оба больших; сохранить активируется лишь после готового аудиодубля. Финальное действие не переставлять местами.
6. Правая перьевая ручка у кожаного планшета — тонкая золотисто-чёрная, разборчивая, не карандаш/не гигантский декоративный меч.

## 2. Реальный конечный автомат

| Состояние | Текст статуса | Центральная спираль | Удалить | Воспроизвести | Пауза/Продолжить | Завершить | Сохранить трек |
|---|---|---|---|---|---|---|---|
| `idle` | «Готово к записи» | **Начать запись** | выкл. | выкл. | выкл. | выкл. | выкл. |
| `requestingPermission` | «Запрос разрешения…» | ожидание | выкл. | выкл. | выкл. | выкл. | выкл. |
| `recording` | «● Идёт запись» | отображает активное состояние; повторный тап не должен порождать второй поток | доступно через подтверждение остановки | выкл. | **Пауза** | **Завершить** | выкл. |
| `paused` | «Пауза записи» | **Продолжить** | доступно с подтверждением | выкл. | **Продолжить** | **Завершить** | выкл. |
| `finished` | «Запись завершена · можно прослушать» | декоративная; если нужен повтор, только через `Удалить` с подтверждением | **Удалить дубль** | **Воспроизвести** | выкл. | выкл. | **Сохранить трек** |
| `previewPlaying` | «Прослушивание» | не запускает микрофон | выкл. пока играет или после остановки | **Пауза прослушивания** | выкл. | выкл. | выкл. до остановки preview |
| `saving` | «Сохранение…» | неактивна | выкл. | выкл. | выкл. | выкл. | `Сохраняется…` |
| `saved` | «Трек сохранён» | закрыть или переход | выкл. | возможно в библиотеке | выкл. | выкл. | выкл. |
| `error` | «Не удалось записать/сохранить» + причина | **Повторить/продолжить**, если возможно | допустимое безопасное удаление дубля | только если есть читаемый файл | по состоянию | по состоянию | только если есть валидный готовый дубль |

**Пауза записи ≠ Пауза прослушивания**, но второй отдельной фиксированной кнопки для предпрослушивания не нужно: в состоянии finished подпись «Воспроизвести», во время preview эта же кнопка становится «Пауза прослушивания». После preview — снова «Воспроизвести». `Пауза` записи отдельно действует только в recording/paused.

В состоянии записи центральная спираль не обязана постоянно оставаться «нажимаемой», но `Начать` и `Продолжить` должны быть отчётливы (подпись/доступность), иначе исходный макет имел бы неоднозначный старт.

## 3. Обработка событий

- При `Start` запросить разрешение `RECORD_AUDIO` на Android с объяснением. При отказе не создавать призрачный файл и не включать таймер; дать понятное действие настроек устройства.
- Запись вести в локальный управляемый временный файл совместимого формата (приоритет штатный Android codec: M4A/AAC, если библиотека/плеер проекта поддерживают; не обещать MP3-энкодер без библиотеки). В библиотеке это аудиотрек независимо от внутреннего контейнера. Ограничение длительности/размера вводить только при реальной технической необходимости, не считать 60:00 из художественного макета утверждённым лимитом.
- `PauseCapture` прекращает добавление audio frames и останавливает таймер фактически записанного содержимого; `Resume` продолжает в тот же логический дубль (если нативный API не умеет, реализовать корректную склейку с неизменной последовательностью, без дублирования).
- `Finish` закрывает захват, проверяет фактические байты и duration, переводит дубль в `finished`. **Не вставлять его сразу в каталог и не добавлять в SessionRun.**
- `PlayPreview` доступно только после `Finish`, должно дать playhead и корректно освобождать аудиофокус/плеер. Микрофон в preview выключен. Закончив предпрослушивание, возвращать `finished`.
- `Delete` из `recording` сначала останавливает захват после подтверждения; из `finished` удаляет только unsaved temp файл и возвращает в idle. Название/теги по возможности сохраняет в форме, чтобы пользователь не набирал их заново.
- `Save` проверяет название, наличие завершённого ненулевого файла, допустимую категорию/модуль; делает атомарное перемещение в managed storage, создаёт `AudioAsset` **один раз** и затем по выбранной опции новый/существующий `ModuleDefinition` recipe entry. После сохранения — вернуться в вызывавшую библиотеку/редактор; если вызвано из структуры, дать явно **«Добавить в текущую фазу/модуль»** (не изменять исходные шаблоны молча). Двойной тап Save не дублирует объект.
- `Cancel` при изменённых параметрах/временном дубле/идущей записи показывает подтверждение «Отменить и удалить несохранённую запись?». При отсутствии дубля — обычный back. Не спрашивать бессмысленно после успешного сохранения.
- Android back, system interruption, app lifecycle, rotation/keyboard должны следовать тому же контракту. Падение приложения не приводит к удалению уже сохранённых файлов. Временные частичные записи можно отдельно восстанавливать/чистить после вопроса, но не считать успешными без чтения.

## 4. Типичная пользовательская последовательность

```
Библиотека → «Записать свой трек» → (имя, теги, категория)
→ (модуль: новый «Мой голос» / существующий «Индукция Элмана» / без привязки)
→ центральная спираль «Начать запись» → «Пауза» → «Продолжить»
→ «Завершить» → «Воспроизвести» → «Сохранить трек»
→ трек виден в «Мои аудиозаписи» и, если выбран, в каталоге модулей
→ фазу «Проработка» можно заполнить этим модулем, даже если у него нет рекомендации «Проработка».
```

Другой сценарий: передумал, нажал `Удалить` → запись очищается, поля могут остаться, можно снова начать. Не путать это действие с удалением уже сохранённого файла из библиотеки.

## 5. Тесты диктофона

1. Чистый `idle`: все 4 нижние действия визуально на месте; запись начинает **центральная спираль**, а не «Воспроизвести».
2. Разрешение есть — таймер и сохранение реального аудио, есть слышимый результат; при отказе нет фальшивого таймера.
3. Запись 10с → пауза 10с → продолжить 10с → завершить: итоговое аудио около 20с, не 30с.
4. `Завершить` не создаёт `AudioAsset`. Только `Сохранить трек` создаёт один.
5. Предпрослушивание после завершения не начинает новую запись. После предпрослушивания сохранение работает.
6. Delete/Cancel удаляют только unsaved take после подтверждения; сохранённые треки не затронуты.
7. Новый модуль при сохранении: в библиотеке аудио + один `ModuleDefinition` с одним треком. Существующий — плюс один recipe entry. Без привязки — только аудио.
8. При запуске из редактора фазы можно добавить сохранённый трек в текущий `ModuleInstance` или отдельным элементом без изменения исходных шаблонов.
9. Повторный Save/долгий тап не создаёт дублей; ошибки накопителя не оставляют битые ссылки на несуществующий файл.
10. Проверить реальную запись на Android, включая Samsung, с блокировкой экрана только если эта функция специально реализована/разрешена; не выдавать такую возможность за готовую без тестирования.
