# Дневник Сульфи: утверждённые решения и строго отложенная реализация

**Статус для ночной работы: REFERENCE ONLY / DO NOT IMPLEMENT IN THIS PASS.** Пользователь прямо запретил последние экспериментальные коллажи и произвольные новые оформления. Они не прилагаются. Дневник продолжим проектировать отдельно после этого ночного пакета.

## Установлено и не подлежит переосмыслению

- Это **авторский дневник/послания Сульфи пользователям приложения**, а не индивидуальный психологический дневник клиента, не соцсеть и не галерея.
- Визуальная метафора: **чёрная кожаная папка-планшет, золотой зажим, тонкое декоративное золотое перо, лист состаренной бумаги**, аккуратная алхимическая символика. Читаемость на телефоне важнее орнамента.
- В записи два содержательных поля: **короткое послание** (фуксия, может показываться на главной) и **полный текст**.
- Читатель: постраничное чтение длинной записи, номер записи, полные дата/день недели/время на первой странице, послание фуксией, основной текст; последующие страницы — продолжение текста; внизу `N из M`, переходы между страницами, возврат на главную и к списку записей.
- Нижняя символика читателя — **ouroboros и алхимический символ серы 🜍**, НЕ символы Люцифера. Сохранить достаточные безопасные поля.
- Оглавление: опубликованные записи по времени, открыть/вернуться, прокрутка и читаемый текст; список также должен поддержать много записей.
- Авторский редактор: послание, полный текст, предпросмотр с точной реальной пагинацией, черновик/публикация, возможность редактировать запись. Черновики и служебные кнопки редактора не должны показываться обычному читателю.
- Облачная публикация ранее обсуждалась как **вариант Google Drive + Google Apps Script** с локальным кэшем для читателей, а не как согласованное и проверенное техническое решение. Не делать публичный write endpoint с секретом в APK.

## НЕ утверждено и требует отдельного последующего ТЗ

- Финальный художественный 9:16 референс авторского редактора и оглавления.
- Auth автора, защищённая архитектура публикации, режим хранения/обновлений и продакшн-API.
- Полная схема статусов, версия записи, редактирование/снятие публикации, кэш и conflict resolution.
- Привязка короткого послания к главному экрану и политика пустого состояния.
- Кодирование и API для облака, настоящие идентификаторы облака и разрешения доступа.

## Ночное задание Codex

**Не создавать и не внедрять новые дневниковые UI-экраны, backend, Google Drive/Apps Script или миграции по этому документу.** Не использовать отвергнутые изображения из истории. Если у приложения уже есть частичный дневник — не удалять его; отметить факт в аудите, сохранить данные, но не менять без отдельного согласования. При желании можно написать нефункциональный `docs/diary_open_questions.md` с техническими рисками, НЕ делать новый пользовательский интерфейс.
