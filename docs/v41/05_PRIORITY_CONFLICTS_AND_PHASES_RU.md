# Контроль приоритетов, конфликтов и этапов — v4.1

## Иерархия требований

1. Неприкосновенность пользовательских данных и работоспособности существующего проекта.
2. `02_PLAYER_FINAL_SPEC_V4_1_RU.md` — новые решения плеера, переопределяет **только соответствующий UI и способ предъявления действий** прежнего v4 §10.
3. `BASELINE_V4/02_UNIFIED_SPEC_V4_RU.md` — остальные функциональные требования приложения.
4. `BASELINE_V4/03_DATA_MIGRATION_IMPLEMENTATION_RU.md` и `04_RECORDER_STATE_MACHINE_RU.md` — специальные подробности миграции и записи.
5. Новый `03_PLAYER_TESTS_RU.md` + `BASELINE_V4/05_ACCEPTANCE_TESTS_RU.md` — совместные критерии приёмки.
6. PNG — визуальная композиция, уступает функциональному тексту и доступности.
7. Все предыдущие v2/v3/v3.1 ТЗ и последние неутверждённые концепты — не источник новых задач.

## Найденные конфликты и разрешения

| Старое условие / визуальная неоднозначность | Финальное решение |
|---|---|
| v4: основная Pause как отдельная большая кнопка на панели | Pause/Resume обязательно доступен, но **только один центр управления на часах**. Android MediaSession сохраняется. |
| v4: отдельные действия `Перейти к выходу` и `Прервать` на экранной панели | На главном плеере **одна** `Завершить сессию`, внутри подтверждения два разных семантических действия; прежняя state machine и статусы сохраняются. |
| v4: описание экрана сессии было обобщённым | Полное поведение по новому точному v4.1 документу; не придумывать новый дизайн. |
| Старый эскиз: колба наполняется при progress | **Колба уваривается: при progress раствор убывает**. |
| Последний PNG показывает много раскрытых треков в неактивных фазах | **Только текущая фаза раскрывает все треки своих модулей**; остальные — фазы + названия модулей. |
| Последний PNG оставляет пустую верхнюю область колбы | **Фаза 1 максимально высоко в доступной зоне**, максимум пространства списку. |
| «Professional»: касание шкалы для перехода к модулю | Только будущая версия, **не в MVP**; в текущем плеере только шесть навигационных кнопок. |
| v4: не делать облако | В этом ночном задании **по-прежнему не делать**. Дневник в проекте обсуждён, но его реализация ещё не согласована целиком. |
| Тема и цифровые данные в PNG | Примеры. Не создавать курение/Элман/даты как наполненные реальные шаблоны. |
| Прогресс «прошло/осталось/всего» при скачках/пауза | Пересчитывать от реального engine, не от list index/отображаемого уровня колбы. |

## Приоритет этапов, если времени / сред не хватает

**Обязателен сначала:** аудит, защита хранилища, валидная сборка, модель timeline, проверка текущих тестов.

**Далее высокоприоритетно:** рабочие базовые функции v4, без которых новый плеер был бы фикцией (очередь, аудио, паузы, запуски/остановки, журнал), затем новый экран и его тесты.

**Затем:** остальные недоделанные v4 модули, диктофон, интерфейсы, адаптивность, миграции/регрессии — в порядке фактических зависимостей, не переосмысляя уже сделанное.

**Ни при каких условиях:** фиктивный APK, «успешные» тесты без запуска, объявление созданного файла MP3, тайные изменения main, слив данных пользователя, прямые write API без авторизации, новые рисунки плеера или дневника.
