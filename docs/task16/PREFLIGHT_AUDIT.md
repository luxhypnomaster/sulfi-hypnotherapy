# №16 — Предпусковой архитектурный прогон (10.11.2026)

**Статус этого документа:** предпусковая проверка СОДЕРЖАНИЯ ТЗ ChatGPT по локальным файлам текущей редакции, ранее сохранённым проектным K/F решениям и официальной документации Google. **Это НЕ аудит выполненного Codex source, не выполненный серверный деплой, не проверенные Android APK.** Codex обязан провести независимый C0 source preflight перед изменением моделей и отчитаться о фактических результатах. Старое №15 исполнено PARTIAL, текущий №16 ещё не запущен.

## I. Обнаруженные и устранённые в требованиях пробелы

1. **Крупный пробел — каталог выгрузки.** Ранее имелись `catalog.list/search/get`, ZIP export и client download, но не полный процесс `author library → редактор аннотации/обложки → публикация → клиентская карточка → selective install`. Добавлен `CONTENT_CATALOG_AND_STORAGE.md`, новые S8/S9 и CAT acceptance. Треки, модули, шаблоны, сборки — отдельные типы; модули указывают точные зависимости. Соответствует принятой модели K-012/013/014/016, не требует stream-preview нескачанного MP3 (K-016).
2. **Нет единой согласованной папки хранения.** Был список абстрактных `config/`, `media/`, `catalog/` без подтверждённого родительского Drive folder и корректного разнесения библиотечных аудио/дневников/модулей. Зафиксирован `Проект Алхимик` → один приватный `Хранилище Сервера Проекта Алхимик`, разделы System/Diary/Library/Media/Packages/Catalog/Technical, bootstrapped idempotently. Drive metadata существующего project root на 10.11.2026: `shared=false`, только user owner; **в реальном облачном bootstrap проверить повторно**, поскольку папочные ACL наследуются.
3. **Физический файл ≠ каталожная карточка.** Отдельные logical `CatalogItem`, immutable asset revisions, `CatalogCard`, status и visibility; переиздание описания без повторного media upload, версии пакетов и точные dependency refs. Публичные API выдаются только для явно опубликованного; наличие файла/папки на Drive не даёт клиенту прав просмотра.
4. **Недостаточно сформулирован client selective install.** Уточнены поток «скачать один трек», «установить модуль + только missing tracks», «шаблон + transitive dependencies», собственные отредактированные копии клиента never overwrite, update notifications, SHA/manifest validation.
5. **Опасность прямых HTTP предположений в GAS.** Официальный GAS Web Apps `e` документирует query/parameters/postData, но не `headers.Authorization`; `ContentService` возвращает текст/JSON, не бинарный HTTP response с Range/206. Задание исправлено: тестируемый JSON POST body token/credential verification без URL secrets; chunked media broker как JSON/base64 либо пользовательский Drive OAuth+точечный ACL, проверять ограничения и реальные bytes. Не имитировать video streaming/CDN, если transport невозможен или слишком медленный.
6. **Версии/безопасность G3.** Прежний №15 audio bytes v1/v2 under same logicalId — P0. Exact `(logicalId, immutableRevision, sha256)`, backup dry-run/rollback; published module must never play latest audio вместо фиксированной версии. Никаких destructive migrations без проверки.
7. **OAuth/Cloud Shell.** Google consent на телефоне был пройден, но callback `localhost:8888` в Cloud Shell не вставлен, `clasp show-authorized-user` не подтверждён, GitHub `CLASPRC_JSON` не доказан. Путь Codex → GitHub Actions → clasp сохраняется; CI без OAuth выполним, реальный GAS project/upload/deploy и Drive bootstrap — **AUTH_PENDING**, пока не предоставлен безопасный завершённый grant. Не использовать одноразовый OAuth code, случайно попавший в чат.
8. **Редакционная формальная проверка.** Требования уже дают запрет сторонних staging Apps Script и изменение старого «Сульфи — дневник», разделяют FakeProvider/CI и live e2e. Исправить у Codex source-test фактическую совместимость manifest, clasp version, auth fail-closed. Матрица №16 должна быть одной валидной Markdown table с уникальными ID и цифрой, совпадающей с metadata; каждый пункт с PASS/partial/blocked/reason/evidence.

## II. Реальные внешние технические факты для Codex, требующие проверки с текущей версией

- Drive folders создаются как файлы `mimeType=application/vnd.google-apps.folder`, `parents=[folderId]`; файлы имеют один parent, поэтому связь трека с несколькими модулями логическая, без размножения объекта по разным папкам. Источник: https://developers.google.com/workspace/drive/api/guides/folder .
- Права Drive обычно наследуются из parent; ограничить их на child можно лишь если применим поддерживаемый limited-access режим. Сначала readback parent ACL, затем создание приватных данных. Источники: https://developers.google.com/workspace/drive/api/guides/manage-sharing , https://developers.google.com/workspace/drive/api/guides/limited-expansive-access .
- Web app functions `doGet(e)/doPost(e)` имеют определённый event object; ContentService даёт TextOutput, не custom binary/Range response. Источники: https://developers.google.com/apps-script/guides/web , https://developers.google.com/apps-script/reference/content/content-service .
- Drive resumable uploads поддерживают продолжение по диапазонам и chunk multiples 256 KiB, но bearer/security, API quotas, mobile OAuth и конкретные вложения подлежат проверке. Источник: https://developers.google.com/workspace/drive/api/guides/manage-uploads .
- Официальный `clasp` поддерживает GitHub Actions с `CLASPRC_JSON`/`CLASP_JSON`, только после завершённого owner OAuth; секреты не коммитить. Источник: https://developers.google.com/apps-script/guides/clasp .

## III. Решения/гейты до выполнения Codex №16

**Gate A (можно выполнить без OAuth):** утвердить единую модель catalog+folders+data-plane, проинвентаризировать реальный task15 Git/SDK provider/LocalCatalog/Capsule/AudioAsset, снять schema/source inventory; backend JS + pure tests, GitHub CI/CD workflows (не вызывают реальный cloud), Flutter UI and transports, две build APK по возможностям CI, no false live URLs. Codex не имеет права сокращать каталог до mock и списывать отсутствующий AUTH на ошибки авторского UI.

**Gate B (требует действительного Google OAuth):** create-once private GAS с точным title, `clasp push/readback` и versioned deploy, `storage.bootstrap` с ACL и exact tree, реальные server guards, catalog first publishing, E2E file bytes. Без grant результат `AUTH_PENDING`/`SERVER_LIVE=NO`, продолжение через checkpoint, один минимальный phone-only action для владельца. Не просить PC.

**Gate C (честная приёмка):** доказать полный мастеровый сценарий: отдельный аннотированный MP3 → Google Drive + catalog published → клиент находит карточку → устанавливает и слушает; затем модуль с существующим треком и новым треком → скачивается только один недостающий трек; переименовать карточку → без повторного аудио; закрыть публикацию → читатель не получает новые bytes, личная локальная копия не удаляется. Также один дневник с текстом/картинками/видео и ZIP, corrupted/dead auth, interruption/resume, exact revision and hash, rollback. **Android physical QA считается NOT_RUN, пока владелец сам не проверил.**

## IV. Остаточные риски, которые ТЗ не имеет права объявить решёнными

- **R1 OAuth секрет отсутствует:** живое создание Server и bootstrap blocked до завершённого consent+передачи в GitHub Secret без утечки.
- **R2 Google Apps Script не полноценный media gateway:** приватное большое видео/аудио может быть непрактичным по задержкам, quota, TextOutput и авторизации; измерения и законный fallback нужны. Не переписывать все data/catalog контракты под другой transport: интерфейс `MediaTransferAdapter` с явно задокументированными capabilities.
- **R3 Выделенная корневая папка проверена как private в момент этой сверки, но ACL меняется со временем:** повторная проверка обязательна, fail closed.
- **R4 Объём большой для оставшейся квоты Codex:** использовать checkpoints C0–C5 и отчёты partial; попытка эмуляции полного live хуже объективного blocker.
- **R5 Отдельный согласованный дизайн K-028/K-008/K-023:** не притягивать полноценный визуальный редизайн или новый Home preview к серверному ТЗ; для каталога строить функциональный минимально изменяющий существующий UI экран.

**Результат проверки ТЗ:** подготовлено к публикации в одном расширенном №16. Это подтверждает только полноту инструкций/матрицы, НЕ реализацию. Реальные исходники Git и Android CI проверяет Codex в C0, облачную публикацию — только после полного OAuth.
