## Runner и безопасная CI-стратегия
- GitHub Actions старые CI runs #44959026009/#44933039652 с `0 steps` из-за billing/spending. Repo теперь public, стандартные runners бесплатно (https://docs.github.com/en/actions/concepts/billing-and-usage); это НЕ доказывает снятие account-level block. Выполнить ровно одну простую дешёвую диагностическую проверку на стандартном runner, если ещё нет свежего подтверждённого SUCCESS. Если опять `0 steps`, не повторять blind retries; явный BLOCKED_ENV, продолжить локально.
- Текущий `.github/workflows/checks.yml` имеет `build_mode=dual-apk` с `check-accepted-server.mjs` и требует подтверждённого live server; не отключать/обходить этот gate. Старые `task18_finalize` и pinned workflows не означают сборку нового исходника. Не вызывать `dual-apk` при незакрытой real server acceptance.
- Для двух OFFLINE/не-production тестовых APK можно подготовить новый **явно изолированный** доверенный manual workflow без stage of live server; отделить от настоящего prod/live release. Его изменения — в draft PR с owner review; до фактического доступного workflow_dispatch на trusted protected default branch не выдавать workflow за запущенный. Секретный тестовый key использовать только в доверенной изолированной job, не в произвольном PR-коде/форках; если безопасная схема запуска невозможна без разрешения на main — `BLOCKED_OWNER`, не поднимать рискованную схему. Альтернатива: build в имеющей signing credentials безопасной среде без публичных ключей и без приватных пользовательских данных, с независимым verifiable report. **Не передавать keystore или пароли в Git/Drive/логи.**
- Минимум два самостоятельных запуска `flutter build apk --debug --no-pub --build-number=<approved>` после pinned dependencies, для CLIENT `--dart-define=SULFI_EDITION=client`; два APK сразу копировать под уникальными именами/хэшами, чтобы второй build не перезаписал первый. Строго сохранить прежнее публичное test signing identity; unsigned ARM bundle не считается APK.
- `apksigner verify --print-certs`, `aapt dump badging`, `sha256sum`/размер/ABI/manifest permissions & exported flags; reverse readback artifacts from independent environment. Целевая пара one source SHA, same code+version, stable package IDs, matching earlier cert; no secrets/literal credentials embedded, no personal data. Изготовить `APK_INFO_25.json` (artifact name, sha256, size, source SHA, workflow link, package, cert, versionCode, android target, build timestamp, result gates) и `INSTALL_25.md` only conditional owner path.
- Отдельные labelled artifacts в GitHub Actions/частной Drive папке для загрузки владельцем только после all P0 & identity PASS; публичный GitHub release/tag запрещён. Репозиторий public: логи/artifact accessibility review, no configs/tokens in artifacts, masked secrets. Факт upload и независимого скачивания/readback проверять, expired artifacts not a durable delivery.
- Если нет пригодного облачного runner, signing/Android SDK or blocked source/data — результат сборки `BLOCKED_ENV/BLOCKED_OWNER`, не создавать новый сертификат и не называться APK-ready. Можно доставить code, tests and release plan PARTIAL.
