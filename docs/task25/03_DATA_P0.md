# Гейт P0: локальная сохранность и миграции, обязательный ДО APK

- Собрать disposable synthetic dataset через историческую **старую native APK UI** при наличии нативной среды (3 tracks, modules/pauses, program, current draft, diary & media, frozen history/checkpoint, pending queue, capsule). Для раннего source-level этапа допускаются Flutter/SQLite FFI fixtures с точными реальными stored bytes; это НЕ native upgrade proof.
- Проверить SQLite schema6/7/8→9 (из копий), 9→9, cold restart, WAL/SHM/journal, interrupted transaction, corrupted/missing database, alternative name/path, legacy migration, owner A→B, offline and missing Google. Не обнулять оригинал, если не удаётся открыть. Сохранить оригинальные IDs, hash of bytes, content revisions, occurrence targets, program dependencies, audio file count, frozen history, owner scope.
- Капсула: inspect immutability, beforeCommit revalidation, malicious ZIP/path traversal, invalid hashes, repeated restore, owner change, cancellation, partial media, sidecars and unknown leftovers. Original DB/audio/capsules never replaced or deleted on failure.
- `scripts/task23/preservation.py` **только** на изолированных копиях с trusted owner assertion + external SHA; no original live DB attachment to Codex. Чтение телефонов владельца, извлечение приватных данных, wipe/cache clear/uninstall запрещены.
- Актуальный штатный update требует: same `applicationId`, same test-signing certificate, monotonic `versionCode`, `adb install -r` on disposable phone/emulator WITHOUT uninstall. Сначала сравнить counts/IDs/sha on real Android for both MASTER/CLIENT. Нельзя выбирать новую пустую DB из-за wrong-path errors.
- Если нет исторической подписанной baseline APK, подходящего старого debug key или пригодного Android, **native gate BLOCKED**. Не подменять его unit-тестом. Если пользовательский installed `versionCode` неизвестен — сборочный кандидат допустим с маркировкой, но гарантировать установку поверх телефона владельца запрещено до readback.
- Отдельная матрица recovery: source-preflight, copy-only, no overwrite; P0-issue causes STOP shipment. Точный исходный MASTER24→25 owner incident без живого snapshot остаётся UNKNOWN даже если все fixtures PASS.
