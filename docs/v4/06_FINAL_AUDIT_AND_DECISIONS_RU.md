# СУЛЬФИ — РЕВИЗИЯ СОГЛАСОВАННЫХ РЕШЕНИЙ И АУДИТ ТЗ v4.0

**Что проверено:** предыдущая v3.1 (`02_UNIFIED_SPEC_V3_1_RU.md`, старые тесты и task), явные окончательные решения в текущем обсуждении, последние утверждённые PNG макеты и графические файлы ZIP. **Что не проверено:** исходный Flutter-репозиторий и работающая APK, поскольку в данном пакете нет исходников текущей версии приложения. Кодекс должен сделать фактический code audit самостоятельно. Поэтому статус «ТЗ готово» не означает «все функции реализованы».

## 2. Найденные противоречия v3.1 и как исправлены

| Код | Было в v3.1 / раннем варианте | Стало в v4.0 |
|---|---|---|
| R1 | «Модуль» пользователя нельзя создать в приложении, только через обновления | Создавать/дополнять `ModuleDefinition` вручную уже сейчас через импорт/диктофон |
| R2 | `Дублировать модуль` — отдельная явная команда | Этой кнопки нет; повторно добавляем один и тот же модуль обычным выбором; повторы в одной фазе разрешены |
| R3 | `Разведка` фактически заложена в базовой поставке | Не создавать готовых шаблонов пока нет контента; только каркас/черновик |
| R4 | Жёсткие рекомендованные связи модуля и фазы, могли не позволять выбрать чужой модуль | Рекомендации — сортировка, в любой фазе выбор всех модулей |
| R5 | Диктофон был «сохранить текущий» без работающей реализации/дизайна | Полный state machine/recording lifecycle + утверждённый новый макет |
| R6 | Старый микрофон как нижний пункт | На главной только четыре утверждённые кнопки; запись доступна в других местах |
| R7 | Нижняя CTA называлась `Записаться`, или временно `К мастеру` | Окончательно **`Записаться к мастеру`** |
| R8 | Главная CTA называлась `Начать сессию` | Окончательно **`НАЧАТЬ ТРАНСФОРМАЦИЮ`** |
| R9 | Ранняя спираль строго геометричная, а одобренный макет — динамичная вихревая | Не менять последний утверждённый художественный макет; имеющиеся геометричные файлы — реальные отдельные ресурсы, несовпадение явно обозначено |
| R10 | Отдельный графический README ещё принуждал старые подписи и старый текст на картинке кнопки | README ассетов переписан; старые PNG с неверной подписью исключены из v4 ZIP |
| R11 | Редактор с четырьмя «блоками» подразумевал и аудио и интервалы | Счётчики фазы/модули/треки/интервалы, время раздельно |
| R12 | Нынешний экран сессии со спорными действиями `Прервать`/`Завершить` | Основная пауза, контекстная работа и явное различие «К выходу»/«Прервать»/штатное окончание |
| R13 | Художественный последний главный экран не показывал карточку текущего шаблона | **Сохранить** обязательную компактную карточку у низа планшета, даже если её нет на статичном макете |
| R14 | Числа/темы на изображениях могли быть восприняты как исходные данные | Запрет переносить демо-тексты, MP3 и темы из художественных скриншотов в APK |

## 3. Оценка готовности пакета

**Содержательно:** согласованные действия, иерархия, экраны и правила хранения закрыты. Новых продуктовых вопросов для старта разработки не требуется. **Технически:** набор достаточен, чтобы Codex мог начать работу, но масштаб — несколько самостоятельных подсистем (модели/миграция, диктофон, Android background, большой UI). Попросить разбивать разработку на проверяемые вертикальные этапы; не ждать, что 80+ регрессионных проверок пройдут без отладки на телефоне.

**Что зафиксировано для избежания бесконечных уточнений:**

- Пустой новый шаблон — каркас с доступными фазами, без фиктивных озвученных сценариев.
- Если аудиотрек не добавлен в модуль, он всё равно остаётся в библиотеке.
- При нажатии `Завершить` диктофон не сохраняет файл; `Сохранить трек` — отдельная операция.
- Если exit-модуль отсутствует, ничего не подставлять; дать возможность безопасно остановиться без ложного заявления об аудиовыходе.
- Нет специальных ограничений на повтор `PhaseType`, `ModuleDefinition` и `AudioAsset`, только уникальные ID экземпляров.

## 4. Реальные открытые ТЕХНИЧЕСКИЕ, а не концептуальные зависимости

1. **URL Telegram и адрес email** пока не предоставлены — конфигурацию подготовить без фиктивных контактов; физическое открытие проверить после подстановки.
2. **Точные классы БД, пакеты Flutter и схема хранения текущей версии** недоступны в этом архиве — Codex обязан изучить репозиторий перед миграцией.
3. **Реальные авторские аудиофайлы для готовых тематических шаблонов пока отсутствуют** — не делать пустые платные/готовые сессии.
4. **Проверка фона и микрофона на Android** требует реального телефона/SDK и разрешений. В задаче прописан метод проверки, не фальшивый результат.
5. **Иконка строгой спирали vs художественная вихревая спираль:** в ассетах есть рабочий файл ранней формы; визуально новый мокап ярче и свободнее. Пока разработчик обязан сохранить **утверждённый макет**; художественный логотип на уровне отдельного launcher-актива может быть точно отрисован позднее без переделки логики. Это известный остаток, а не отмена утверждения.
6. **Экран выполнения реальной сессии:** пользователь отметил, что там «каша», но не предоставил финальный утверждённый полноэкранный макет. Поэтому жёстко утверждены **поведение и названия действий**, а конкретное визуальное расположение поручено Codex по действующей дизайн-системе без ненужных кнопок.

## 5. Проведённая проверка на противоречия

- Сопоставлены решения по терминологии и созданию модулей с последними явно высказанными пользовательскими корректировками; удалено запрещающее правило из v3.1.
- Проверены существующие локальные файлы PNG для главной, диктофона и золотых часов: они реально присутствуют в данном контейнере и включаются в ZIP.
- Исключены устаревшие изображения кнопки с неправильной подписью и переписан README графики.
- В тестовую матрицу включены повтор того же модуля в одной фазе, создание модуля через импорт, четырёхкнопочный диктофон, фоновый таймер и восстановление прерванной истории.
- Добавлена программная проверка целостности каталога/обязательных решений в `scripts/audit_package.py`; её результат фиксируется в пакете в `08_AUDIT_RESULTS.txt`.

**Итог:** выпускаем **v4.0 как единственный актуальный пакет для Codex**. **Готовность ТЗ ≠ готовность Android-приложения**. Все технические зависимости указаны открыто.
