# G4 — понятная работа без ожидания на одном экране
## Существующее — переиспользовать
По Android-скринам: в Библиотеке облачный значок открывает «Облачный каталог»; внутри есть «Мои публикации» и «Очередь передач»; каталоговые draft и failed доступны. Предпросмотр дневниковой записи уже вызывается нажатием на строку. НЕ добавлять ещё одну кнопку предпросмотра.
## Обязательные UX изменения
1. В мастерской нижней навигации явно различить «Библиотека» и «Каталог» (или эквивалентно подписанные доступные действия в рамках уже существующей утверждённой геометрии). Значок облака без подписи не может быть единственной точкой входа. Не перерисовывать фоновый кожаный планшет, не менять палитру и кобру/плеер.
2. Сделать отображение общей существующей очереди на разных экранах: компактный верхний индикатор с числом задач/названием материала/байтовым и этапным прогрессом. Нажатие возвращает к подробной очереди, где есть phase, bytes, retries, pause, resume/cancel и last error. Прогресс отдельного файла не выдаётся за завершение публикации.
3. После постановки в очередь пользователь возвращается в приложение, не остаётся заблокированным редактором. При выходе с несохранённым черновиком должен быть prompt/save/autosave; сама передача локально сохраняется и продолжается при навигации внутри приложения. При сворачивании Android — исследовать platform restrictions; при невозможности надёжной background execution показывать честный статус/notification, а не обещать guaranteed background. Foreground service только при оправданном длительном transfer и по Android policy с видимым уведомлением.
4. Не допускать одновременных дубликатов при repeated taps/двух карточках одного модуля; safe cancel/pause не удаляет исходный audio. Статусы читабельны по-русски и имеют детальный диагностический код отдельно. Ошибка DNS не должна называться «Войдите через Google», а подтверждённый 401 должен вести к безопасной повторной авторизации.
5. Клиентская навигация к каталогу и дневнику должна быть понятной для неопытного человека, но полный redesign или клиентская витрина «Программы» — отдельная задача следующего этапа.
6. Референсы в `evidence/` — скриншоты фактической APK24, не художественные макеты; при UI изменениях приложить реальные Flutter screenshots и два Android-подтверждения, без генерации произвольного нового стиля. Использовать 9:16 только для новых иллюстраций/макетов согласно правилам проекта.
