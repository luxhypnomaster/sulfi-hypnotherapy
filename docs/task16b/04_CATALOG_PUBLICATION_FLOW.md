# G3 — каталог, публикация, ContentLink и обложки
## Утверждённая продуктовая логика
- **Добавить в каталог** — самостоятельное действие: локальный трек/модуль/шаблон → metadata + dependency graph → авторизованная безопасная загрузка → SHA/readback → material AVAILABLE in catalog per chosen visibility. Дневниковый анонс не создавать.
- **Подготовить к публикации** — отдельное действие, открывает редактор анонса; если материал уже в каталоге, выбрать exact `contentId@revision` и опубликовать дневник БЕЗ повторной загрузки audio. Если материал ещё локален, объединённый процесс сначала загружает и верифицирует его, затем создаёт дневниковую публикацию с ContentLink. Ошибка каталога удерживает дневник как локальный draft, не создаёт битую ссылку.
- **Редактировать** — существующее локальное действие.
- **Экспортировать на устройство** — нынешний локальный ZIP, сохранить и переименовать UI для устранения двусмысленности. Перенос одной функции в другое меню не означает её удаления.
- Ссылка на уже опубликованный module должна указывать exact immutable revision/dependencies; повторный анонс = новое сообщение в дневнике, не новое копирование в каталоге.
## Карточка и черновики
- Существующий список каталоговых черновиков `draft/failed` НЕ путать с черновиками дневника. Выход/рестарт не теряет название, аннотацию, описание, категории и cover, прогресс/возобновление показываются из той же очереди. Должен быть понятный путь из меню модуля к существующему draft, без дублей по repeated tap.
- **Аннотация** (краткое представление в каталоге) и **Описание** (подробности) получают короткие inline пояснения; existing fields/IDs/legacy metadata не ломать. Не удалять уже внесённые тексты пользователя.
- Категории — drop-down multi-select (с сохранением существующих значений; механизм новых категорий с валидацией и без внезапного глобального изменения). Категория публикаций не равна категории дневников.
- Обложка: выбор изображения из устройства → немедленно локальный preview и безопасный локальный persisted copy → отдельный upload с SHA/size/type validation, status локально / передаётся / сервер проверил / опубликовано. Сетевой сбой не должен сбрасывать preview/отбрасывать локальный файл. Отсутствующая обложка в старом модуле не препятствует открытию каталога. Публикация при ошибке картинки: явно выбранная политика (обязательность/необязательность), не silently ignore.
- Контракт cover/metadata должен позволять последующую визуальную витрину модулей и «Программ», но НЕ реализовывать K-033/K-034/035/036 в текущем №16-Б. Не создавать новую сущность Program вместо existing template.
## Проверки безопасности
MASTER может add/publish/withdraw по подтверждённой роли; CLIENT может только читать/install опубликованное, даже при вызове API напрямую; unpublished draft не раскрывается. Повторная публикация journal без клиентских разрешений FAIL CLOSED. Test proofs required.
