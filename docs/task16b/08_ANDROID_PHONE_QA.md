# Ручной приёмочный сценарий владельца — два телефона
## До начала
Обновить MASTER поверх рабочей APK24, не очищая данные; установить CLIENT как отдельный package. Сохранить локальную библиотеку и её независимую резервную копию. Проверять только новую пару подписанных candidate APK после Codex. Указать версию/build и hash. Не публиковать материалы клиента/пользователя без согласия.

## A. Авторизация — 2 аккаунта
На MASTER: человечек sign-in, whoami MASTER, щит проверка прав, переходы в библиотеку/каталог/дневник, выход на главный экран/сон/перезапуск, обновление дневника. Повторить после 10–15 мин и при переключении Wi-Fi/mobile; не должно произвольно требовать вход при временной потере сети. На CLIENT: sign-in другим аккаунтом, роль CLIENT и принудительный denial publish, дневник/каталог read; logout явно по кнопке работает.

## B. Каталог без дневника
На MASTER у существующего «Индукция Элмана вариант 2» (3 трека) меню → «Добавить в каталог». Картинка (если выбрана) сразу видна локально. Подтвердить upload queued; выйти в другие разделы, вернуться в очередь. Дождаться server verification/commit и проверить в «Моих публикациях». Отправленные байты и successful catalog record — два отдельных события.

## C. Анонс без повтора медиа
В «Подготовить к публикации» выбрать существующий server module и создать дневниковое сообщение с точной ContentLink. Убедиться, что модуль / 3 трека НЕ отправляются второй раз. Обновить CLIENT дневник; открыть ссылку и карточку каталога. Если выбран объединённый путь для другого локального материала: каталог commit ДО дневникового publish.

## D. Client install/offline
CLIENT скачивает published module + exact 3 tracks, сверяет порядок и SHA. Повторная установка без дублирования byte blobs, local copies не перезаписывать. Включить авиарежим, воспроизвести все треки с экраном в lock; после restart запись/модуль присутствуют. При отказе/withdraw не трогать уже установленную локальную копию в рамках политики.

## E. Fault injection
Прервать сеть в середине второго трека (Wi-Fi off/airplane), вернуться online; очередь recover без потери черновика, без дополнительных каталожных дубликатов и без логина при временном сетевом сбое. Проверить отмену/паузу и screen navigation. При отказе auth показать точный код и возможность вручную переавторизоваться. Повторно открыть карточку/очередь после принудительного закрытия приложения — сохранение статуса, данных и отсутствия дублирования.

## Сбор доказательств
MASTER/CLIENT screenshots основных статусов, время входа, время байтовой передачи и серверной верификации, версия/сеть/два аккаунта (без email), итоговый PASS/PARTIAL/BLOCKED по каждой цепочке. Все личные файлы остаются на телефонах. Если этап заблокирован — следующие отмечать NOT_RUN, не замещать UI-скринами.
