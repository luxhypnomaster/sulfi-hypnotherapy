# Ресурсная дисциплина Codex и отчётность по этапам

## Режим исполнения

Стабилизировать конкретные существующие механизмы из PR45/46, не начинать новый rewrite. Цель №16-Г — продуктовые P0, не избыточное доказательство каждого гипотетического случая. Контроль P0 storage/auth/security строгий. Адресные тесты на каждом изменении; **полные регрессии после финального кодового изменения**, а не после каждой правки текста; при изменении рисковой подсистемы её полный набор тестов обязателен.

1. G0: один снимок фактов и diff/graph, по нему narrow patch. Не перечитывать весь архив и не перепроверять каждую прежнюю PASS матрицу.
2. Отчётность: один checkpoint по G1/G2/G3/G4 (строка: код, сколько тестов, что сломалось, next), затем итоговый RESULT/CHANGES/TESTS/ISSUES/ACCEPTANCE. Evidence хранить ссылками на CI и SHA; без раздутых дублирующих архивов.
3. Одна и та же ошибочная native automation повторяется не более **двух раз без новой гипотезы**. Если причина в harness/focus/file picker — фиксировать тест или BLOCKED. Не превращать CI artifact quota exhaustion в бессмысленные повторы.
4. При зависшем/неисправном стороннем API, Google auth без реального аккаунта, серверном одобрении — явно отдавать owner gate, не имитировать service PASS и не пытаться «победить» бесконечными имитациями.
5. `CODEX_EFFICIENCY_16G.md` должен содержать по стадиям: CI URL; тип теста; запусков/повторных запусков; причину повторов; продолжительность при доступности; сколько PASS/PARTIAL/BLOCKED; новые и повторно используемые проверки; какие циклы можно было исключить. Без выдуманных чисел об оставшейся квоте.
6. Лимиты 5ч и неделя отдельно: пользователь сообщает остатки до и после сессии; не прибавлять/вычитать через сброс и не относить расход параллельных Work/Codex сессий только к данному ТЗ. ChatGPT вносит в журнал https://docs.google.com/spreadsheets/d/1Nqry0ITE_6dkfZ76e4Vp7bttPSHi7kwakporKuEI2bw/edit . Отчёт Codex НЕ должен запрашивать у себя «израсходовано X%».

## Условия остановки

- Подтверждённая угроза уничтожения пользовательских данных или раскрытия чужого аккаунта → STOP-SHIP APK, оставить branch/tests/reports.
- Требуется изменение production GAS, OAuth ACL, main, signing или чужих данных → **STOP AND ASK OWNER** (предоставить plan/patch до воздействия).
- Не воспроизводится Google OAuth/draft без реального владельца → marking NOT_RUN/OWNER_QA, перейти к допустимой независимой части без ложного PASS.
- Падение эмулятора дважды с одинаковой причиной без новой гипотезы → BLOCKED harness, оформить конкретный workaround или согласованную физическую проверку.
- Закрыты G1/G2/G3 controlled gates → готовить G4, не заказывать новые исследования конкурентов, анкет и курсов.

## Критерий экономии

Сравнивать расход *недельных процентных пунктов на принятый проверенный результат* между 3–5 сходными задачами; параллельно следить за P0/P1 regression rate и повторными test runs. Сокращение лимита при ухудшении реального качества — НЕ успех.
