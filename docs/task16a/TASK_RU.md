4. РОЛИ, ПОЛНОМОЧИЯ И ИДЕНТИЧНОСТЬ

На первом этапе две основные роли: MASTER и CLIENT; GUEST — только если предусмотрен явно разрешённый анонимный публичный просмотр. Единственный мастер — верифицированная Google-идентичность владельца luxhypnomaster@gmail.com; сервер должен закрепить проверенный Google sub/owner identity из доверенного источника, а НЕ доверять тексту email из JSON запроса или локальному признаку APK. Не раскрывать owner sub в открытых отчётах. Любой другой пользователь с корректно проверенным Google ID-токеном автоматически имеет роль CLIENT. Никаких белых списков клиентских почт. В будущем допускается расширение ролей, но сейчас не вводить административные приглашения/подписки.

Роль определяет СЕРВЕР по подтверждённому пользователю, не тип APK. Пользователь-мастер в клиентской APK остаётся мастером на сервере, но клиентский UI не обязан показывать мастерские функции. Сторонний пользователь даже в мастерской APK не получает привилегий публикации. Не доверять userId/role/email, переданным клиентом напрямую.

Google ID token: проверить подпись по официальным ключам Google, issuer, aud (точный Web Client ID), exp, iat/nbf при наличии, email_verified и стабильный sub; иметь защиту от поддельных/истёкших/чужих токенов, неправильного audience и повторного применения отозванных грантов. Credential передавать только по предусмотренному безопасному транспортному контракту POST; не утекать в URL/логи/redirect.

Сервер остаётся исполнителем от имени владельца для Drive, а пользователь НЕ получает прямые разрешения на приватный Drive. Право клиента на публичные материалы проверяется сервером; доступ к личным/частным файлам чужого пользователя запрещён. Разделение данных по проверенному sub, безопасные logout/account switch, запрет кросс-аккаунтного использования локального кэша и отложенных очередей.

5. МАТРИЦА ЭКСПОРТА/ИМПОРТА И КАТАЛОГА

MASTER: вход через Google; создание/правка собственных треков, модулей, шаблонов; публикация в общий каталог; публикация и снятие дневниковых записей; просмотр собственных административных статусов; чтение и установка опубликованных материалов.

CLIENT: вход через Google; просмотр опубликованного каталога и опубликованного дневника; скачивание и установка разрешённых треков/модулей/шаблонов и зависимостей в СВОЮ локальную библиотеку; собственные локальные сессии/копии. НЕТ доступа к публикации или изменению общего каталога, приватных авторских данных и материалов другого клиента. Локальный экспорт/резервное копирование СВОИХ файлов не должен смешиваться с серверной публикацией.

GUEST без входа: только явно открытые публикации, если это действующая политика. Анонимная запись, публикация и доступ к приватным ресурсам запрещены.

Для пилота опубликованный контент бесплатен для всех авторизованных клиентов, без оплаты, подписки, пробных лицензий или искусственных лимитов пользователей. Сохранить на сервере расширяемую модель разрешений на будущую платную выдачу, но не делать сейчас неиспользуемый платёжный интерфейс.

Различать два действия:

(a) «Добавить аудио в дневник»: аудиосообщение/послание для воспроизведения внутри записи, НЕ становится автоматически библиотечным треком и НЕ получает кнопку установки.

(b) «Добавить из каталога»: точная ContentLink-ссылка на опубликованный трек/модуль/шаблон с исходным contentId/revision/digest. В дневнике — карточка и установка через ЕДИНЫЙ catalog installer. Только опубликованный каталог источник устанавливаемых материалов; нельзя обходить права или скачивать unpublished/withdrawn только потому, что ссылка записана в дневнике.

При установке модуля подгружаются ТОЛЬКО недостающие точные аудио-ревизии, проверяются SHA/состав и сохраняется происхождение («официальный / заводской»). Личная изменённая копия клиента остаётся отдельной; обновление оригинала её не перезаписывает. После снятия публикации нельзя начинать новую установку, но уже установленная офлайн-копия сохраняется в рамках согласованной политики.

Задача Codex: АУДИТ текущих UI и кода — подтвердить или исправить в пределах №16 кнопку публикации модуля/шаблона, редактор дневника «Добавить из каталога», клиентский экран установки. Не считать автоматом, что все UI уже прошли физический Android.
