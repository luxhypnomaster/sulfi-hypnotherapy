# ЗАДАНИЕ №17 — Стабилизация авторизации, очереди, публикаций и каталога Сульфи

**Проект:** «Алхимик» / «Сульфи» · MASTER и CLIENT · 13.11.2026.
**Статус:** новое самостоятельное корректирующее ТЗ на основании полевых испытаний APK26, без признания №16 завершённым.
**Порядок выполнения:** G0-аудит → G1 Google session и роли → G2 привязка очереди и безопасное возобновление → G3 живой обмен и каталог → G4 критический UX → G5 контрольная сборка, физическая приёмка и отчёт. Не начинать G3, пока не установлен G1/G2 root cause и не проверены их базовые инварианты.

## Критерий конечного результата

На физическом телефоне A под реальным Google MASTER: авторизация сохраняется через перерывы/перезапуск/изменения сети; модуль «Индукция Элмана» из **трёх настоящих треков** и программа (пользовательское название старого template) публикуются в официальный облачный каталог с верифицированной серверной квитанцией. Мастер может разместить отдельную дневниковую публикацию с действительной ContentLink на опубликованную версию. На физическом телефоне B под **другой** Google CLIENT: каталог доступен, выбирается модуль/программа, устанавливаются необходимые файлы без дублей, три аудио проигрываются офлайн. Запрет CLIENT на публикацию подтверждён. Один и тот же MASTER не вынужден повторно входить в Google при переключении экранов или обычном истечении временного токена.

Текстовая дневниковая публикация с изображением **уже однажды реально прошла** MASTER26 → сервер → CLIENT25. Это только частичный PASS; каталог и установка ранее физически не подтверждены. Не стирать этот факт и не считать полноценным E2E.

## Непереговорные границы

1. Не создавать новые Google OAuth проекты, новый GAS, сервер или каталог в обход существующего, не менять нынешний Drive-владелец, ACL, public scopes и Android package/cert. Существующий GAS6: **не обновлять в production без отдельного разрешения владельца** после read-only анализа diff, плана отката и доказательств. Не деплоить в legacy Apps Script «Сульфи — дневник».
2. Не сливать изменения в `main`, не открывать private GitHub draft/репозиторий, не менять ключи подписи, не требовать новых платных сервисов и не открывать посторонним личные данные без явного разрешения.
3. Не удалять приложение/данные, не чистить SQLite/медиа/sidecars, не делать downgrade; не возвращать unsafe orphan GC или silent reset. Работать поверх установленной версии. Реальные пользовательские исходники защищены.
4. Прежние №16 / 16-А / 16-Б / 16-В / 16-Г, оригинальная матрица 147 критериев и отчёты сохраняются. Новое ТЗ не переводит чужие PARTIAL в PASS. Не удалить активный `Задание_16.zip`.
5. Не подменять живой Google sign-in/Drive/2 Android fake provider-ом и зелёным CI. Статус `BLOCKED_OWNER` при необходимости реальных устройств — честный и допустимый.
