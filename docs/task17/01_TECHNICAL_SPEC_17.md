# №17 — ТЕХНИЧЕСКОЕ ЗАДАНИЕ

## 0. Цель и наблюдаемые факты

Поставить устойчивую авторизацию **как фундамент** и на её основе довести публикацию дневника, каталожных модулей/программ, получение CLIENT, выборочную установку и офлайн-воспроизведение. Это НЕ отдельное «только Google Auth» и НЕ редизайн.

Полевые факты MASTER APK26: после Google login около 15 минут спустя редактор снова вызвал account chooser; появлялось «Аккаунт изменился. Задача приостановлена», хотя server UI подтверждал MASTER. Из одной мастерской учётки на одном телефоне и отдельной CLIENT-учётки на другом **не делали переключения Master→Client внутри MASTER**. Очередь показывала задачу «тесты 666» `USER_PAUSED / 0 из 0 байт / 0 попыток` и другую «Индукция Элмана вариант 2» `WAITING / 0 попыток`; попытки «Продолжить» без результата. В дневнике есть одна реальная подтверждённая доставленная на CLIENT25 запись с картинкой; статус читателя «Черновик» неверен. Строка «Добавь себе в библиотеку» в той записи — авторское **короткое послание**, НЕ кнопка и НЕ ContentLink. Не исправлять как дефект кнопки. Дневник до входа показывал 0 и не позволял создать запись, после входа прежние черновики проявились: offline-local MASTER должен работать независимо от Google.

Каталог найден в `Библиотека → Облачный каталог`; первоначально предлагал вход для личных публикаций, а после перехода через дневник признал вход и показал «Выйти». Это **не доказывает** разные auth backend, скорее shared session/recovery timing; публикации после этого по-прежнему не возобновились. Нельзя объявлять, что проблема только в токенах, т.к. запросы иногда не начинались. Нужно проследить точный guard/state transition.

На главном экране фуксиевый щит у уха Сульфи малозаметен; он открывает `Ваше пространство`, где нет управления Google. В sheet версии показывается `0.4.12+17` при ожидаемой ранее MASTER26 `0.4.18+26` — проверить отображаемую версию vs фактический package read-only, не объявлять причиной миграции.

## G1 — Google session & серверные права MASTER/CLIENT

- ЦЕЛЕВОЕ UX: первый интерактивный вход Google → после этого выбранная подтверждённая identity и user intent persistent при background/resume/cold restart. Стандартный token expiry вызывает безопасный **silent restore/refresh** штатными SDK/platform механизмами; пользователь не выбирает аккаунт каждые 15 минут и не входит вручную при переключении дневник↔каталог↔публикация. Временная network ошибка = OFFLINE/RETRY, НЕ signed-out.
- **Явный «Выйти»** сохраняет намерение signed-out; ни automatic sign-in, ни queued network resume под старым аккаунтом до нового подтверждения. `Сменить аккаунт` явно инициирует выбор, не полагается на UI флаг «Автор». Реальные revoke/consent-required или неуспех silent recovery допускают видимый вход с причиной, не бесконечный spinner. Сохранить уже наблюдавшееся успешное завершение однажды инициированного Google-login после восстановления сети, даже при выходе из экрана, с bounded retry/backoff.
- Один единый session/auth controller или эквивалент единый источник состояния для всех entrypoints и обеих редакций; исключить независимые login loops и race при одновременных запросах (single-flight refresh; отмена старых transitions после explicit logout/switch). API получает короткоживущий актуальный credential по безопасному контракту, не хранит ID/access/refresh токены plaintext в SQLite/логах/ZIP/codex output. Не строить собственную небезопасную систему бессрочных refresh tokens.
- На сервере каждый защищённый запрос проверяет действительный Google ID token по подписи/issuer/audience/expiry/sub, роль по server-derived allowlist/permissions. `sub` — стабильный идентификатор owner, не email, не token и не локальная роль APK. MASTER может публиковать, CLIENT только читать/устанавливать разрешённое. CLIENT не запрашивает Drive scope пользователя; Drive выполняет сервер в рамках контролируемых разрешений. `401` (missing/expired/invalid) → допустимый silent refresh + один bounded retry; `403` (действительный пользователь, но прав нет) → запрет без повторного picker и без обхода; `NETWORK/DNS/TLS/5xx` → отдельные человекочитаемые состояния без wipe. Не скрывать системное предупреждение об unsafe redirects; валидировать Google Apps Script redirects только к проверенным ожидаемым Google endpoints, не пересылать secrets в URLs/на чужие hosts.
- MASTER local drafts/images/audio доступны создавать/изменять/читать **офлайн и до Google login**. Приватные облачные публикации и owner-scoped задания только соответствующему server-verified `sub`; локальные личные данные других аккаунтов не проявляются через auth fallbacks.

## G2 — Очередь как согласованное продолжение идентичности

- Изучить existing persistent durable queue, НЕ создавать вторую. Сетевые задачи связаны с immutable проверенным Google `sub`/owner scope и объектом+ревизией+операцией, а не токеном или изменчивым accountHash. Guard от стороннего аккаунта fail-closed. Если текущий owner достоверно **тот же**, поддержать безопасное `Resume` после нового токена/same-user re-login и возврата из lifecycle pause. Если owner не подтверждён или другой — quarantine с объяснением и без cross-account отправки.
- Отдельные состояния: `PREPARING`, `QUEUED`, `WAITING_NETWORK`, `WAITING_AUTH`, `WAITING_PERMISSION`, `RUNNING_UPLOAD`, `VERIFYING_SERVER`, `PAUSE_REQUESTED` (после текущего запроса), `PAUSED_BY_USER`, `PAUSED_LIFECYCLE`, `PAUSED_OWNER_CHANGED`, `FAILED_RETRYABLE`, `FAILED_PERMANENT`, `CONFIRMED_COMMITTED`. Не обязательно менять существующие enum/БД буквально: UI/backend должны достоверно различать семантику. `USER_PAUSED` не устанавливать для network/auth/owner/lifecycle без действительно user-triggered pause. Учитывать Android кооперативную паузу в фоне: НЕ заявлять передачу при свернутом приложении, если foreground service не реализован.
- В случае ручного logout не возобновлять автоматически. После явного повторного входа того же owner — восстановить/перепроверить доступность задачи и предложить «Продолжить»; если previous receipt уже есть, не повторять. `Resume` должен давать observable попытку либо конкретный reason, почему не может. Нет endless loops, бесконечной проверки в фоне или перезагрузки всех media.
- **Три уровня idempotency** для публикаций: UI блокирует повторное нажатие до завершения durable enqueue; очередь хранит уникальную задачу для (owner, operation, contentId, revision) и при повторном tap возвращает её; сервер перед commit принимает стабильный ключ и даёт idempotent receipt/lookup, в том числе если сетевой ответ потерян. Не публиковать дважды при retry/перезапуске. Новая ревизия того же contentId и копия «Создать на основе» с новым contentId — разные операции.
- Исходники, drafts, локальная библиотека, старая публичная редакция остаются до authoritative commit; подтверждение отправки байтов не означает публикацию. До retry uncertain commit — inquire server status. Отмена задачи не равна снятию уже опубликованного материала.

## G3 — Реальный cloud flow: дневник отдельно, каталог отдельно

**Дневник:** Авторская запись может состоять только из непустого заголовка и короткого послания; дополнительные text/image/audio не обязательны. Разрешить медиа и существующий reader. Команда «К публикации» → mandatory preview всех страниц (посетить каждую, проигрывать аудио целиком не надо; не меняет reader read-status) → финальная «Опубликовать» → атомарный enqueue → выход из editor в карточку задачи очереди. При ошибке enqueue остаться в редакторе и сохранить данные. Сообщения статуса в списке: черновик, ожидает/передаётся/проверка, server-confirmed published, снято/expired, error/paused. Синхронизировать публичный reader: он не должен показывать «Черновик» у подтверждённой публикации. `Опубликовано · есть черновик` у автора — только если есть реальная последующая незданная редакция. Строка `Добавь себе в библиотеку` в уже полученной записи — пользовательский текст, НЕ CTA; не превращать в кнопку.

**Каталог:** `Модули/Программы → Добавить в каталог` — техническое размещение exact versioned catalog object (модуль, программа = существующий template), dependency manifest (фаза/модуль/трек/пауза), медиа hashes/size/revision, server receipt и разрешённая выдача CLIENT. НЕ создавать автоматически дневниковый пост. `Библиотека → Облачный каталог` — существующая точка чтения/установки. Отдельная дневниковая запись может сослаться на **уже подтверждённую** exact ContentLink (contentId/revision) с install CTA только при реальном доступном каталожном материале; без ссылки обычное короткое послание остаётся текстом. Полный контроль: MASTER публикует один модуль с 3 треками, одну программу на существующих IDs и потом дневниковый анонс с ContentLink; CLIENT другой identity видит, скачивает зависимости, запускает все 3 аудио офлайн. Повторная установка и общий track не дублируются.

**Транспорт:** Подтвердить реальные bytes, hash, MIME, серверный commit, ограничения Apps Script и Drive. Не утверждать, что GAS автоматически виноват. Для redirects/cache/Network/DNS/TLS дать диагностические коды, bounded retries и stop conditions; после исправления auth/queue отделить transport bugs измерением с двумя телефонами. Приватный каталог owner-only по verified subject, public catalog только разрешённое, CLIENT forbidden для publish и privacy leak. Не менять existing live GAS6 без владельца: если backend patch обязателен, готовить изолированный audited diff, plan, rollback и STOP WAITING_APPROVAL, не форсировать deploy.

## G4 — Узкий UX для работы, без тяжёлой «Стены»

- Существующий home shield около уха Сульфи сделать **кислотно-жёлтым** как CTA «НАЧАТЬ ТРАНСФОРМАЦИЮ», заметным на фоне; его `Ваше пространство` сверху содержит общий Google status, выбранный аккаунт (по безопасным UI-правилам), server-confirmed MASTER/CLIENT, «Войти», «Сменить аккаунт», «Выйти», при необходимости «Проверить права». Локальный переключатель `Режим: Автор` не доказывает серверную роль. ZIP/backup/local catalog/delete остаются без изменений, опасные команды с подтверждением. Единый session state с дневником и каталогом.
- Global `Передачи: N` — **жёлтый** индикатор; открывает существующую очередь и карточку конкретного задания. При известном total — progress bar + % + N/M байт; при verification 0/0 байт не изображать 0% upload, честно «Проверка на сервере». `Пауза` / «Пауза после текущего запроса» / «Продолжить» должны соответствовать действительному state. Код ошибки в деталях, человеку понятная причина.
- В списке дневника четыре основные пиктограммы состояния: фуксиевый блокнот черновик, жёлтая отправка, зелёная галочка server confirmed, серый снято/завершён срок. Error/paused — явное текстовое дополнение. Состав `Текст/Изображение/Аудио` фуксией, не ярко-зелёным. Уплотнить редакторские действия, но **не строить медиаленту/комментарии сейчас**. Существующую Android Back-навигацию reader НЕ менять — она проверена и корректна. Перелистывание между ЗАПИСЯМИ отдельно от существующих prev/next СТРАНИЦЫ — P1, если не мешает P0.
- Каталожная карточка: устранить потерю фокуса/слетание курсора при вводе; сохраняемый редактируемый профиль автора/правообладателя по умолчанию (НЕ безусловное присвоение Google identity прав собственности). Категории `Индукция`/`индукция`: определить scope/источник, сохранять category IDs и все связи, предотвратить новые case/whitespace-дубли без destructive merge. `Личный материал` / `Для всех читателей`: проверить фактический ACL; подписки/профессиональные аудитории сейчас не вводить. Полноценный remote «Управление каталогом» с rename/merge/reassign/archive — отдельный следующий этап, не блокирует E2E.
- Проверить displayed `Сульфи · 0.4.12+17` в `Ваше пространство` против реального APK version/package и убрать жёстко зашитый устаревший номер. Сохранять user data.
