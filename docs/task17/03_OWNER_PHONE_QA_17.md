# №17 — физическая приёмка на двух Android (MASTER + CLIENT)

**Не запускать этот сценарий до отчётов G0/G1/G2 и предоставления проверенной пары APK с безопасной подписью.** Owner QA делает владелец, а не Codex, если доступ к физическим телефонам невозможен. Не просить пароль, токен, приватный текст или аудио для отчёта. Записывать результат кратко: PASS/PARTIAL/BLOCKED/FAIL и безопасный код этапа.

## Подготовка

Телефон A: установлен MASTER26 обновлением поверх MASTER25, мастерский Google; телефон B: CLIENT25 на другом телефоне, другой Google. Уточнить фактическую installed version/package для обоих перед обновлением; не предполагать CLIENT26 уже установленной. Все тестовые файлы заменимые, оригиналы отдельно. Ни `uninstall`, ни `clear data/cache`, ни `downgrade`, ни повторная загрузка APK без сверки SHA/подписи. При обнаружении DB/cert warning — STOP, зафиксировать и сохранить исходники. Роль «Мастер» удостоверяет сервер, а не локальная кнопка «Автор».

## Приёмочные сценарии по порядку

1. **HOME-AUTH.** Открыть кислотно-жёлтый щит → «Ваше пространство» → блок Google account. Один раз выбрать реальный MASTER Google; проверить отображение подтверждённой роли. Из дневника открыть каталог `Библиотека → Облачный каталог` (public, owner personal), затем публикационную карточку, вернуться назад. Нового picker без реальной причины быть не должно. Сверить версию APK в UI и в Android.
2. **RESTORE.** После 15, 30, 60 минут без ручного выхода, app background/foreground и cold restart вернуться в дневник и каталог: роль и выбранный аккаунт восстанавливаются без повторного picker. Если token expires, silent restore; явный revoked access — понятная ручная повторная авторизация. Синхронизация одной первой попытки не должна выдавать вторые независимые окна входа.
3. **NETWORK.** На заменимых данных временно отключить интернет; в MASTER открыть/изменить/создать локальный черновик с media, он должен сохраниться. В каталоге статус offline, ничего личного не исчезает. Включить интернет: auth корректно восстанавливается, не считывая другой аккаунт. Если login инициирован без сети, он может завершиться после восстановления в фоне, без CPU polling-loop.
4. **LOGOUT.** Выйти вручную → cold restart: приложение само не вошло; локальный черновик доступен. После добровольного входа в тот же MASTER записи видны, статус owner-bound задач reconciled; старые чужие задания не переслались сами при logout. При другом пользователе на тестовом аккаунте — старые owner задачи недоступны к отправке.
5. **QUEUE-CAUSE.** На заменимой задаче проверить причину `PAUSED`, разные `USER`, `LIFECYCLE`, `WAITING_NETWORK`, `WAITING_AUTH/OWNER`. `Продолжить` либо вызывает конкретную попытку, либо даёт диагностическую причину без ложного «выполняется». Не отменять неизвестную старую реальную очередь; новые операции с отдельным ID.
6. **DIARY-SHORT.** Создать заголовок + короткое послание **без** другого блока. `К публикации` → посетить страницы preview → `Опубликовать` один раз → переход в очередь. Пять быстрых повторных тапов не порождают больше одной задачи. При offline — enqueue сохраняется, в editor не теряется написанное. После server receipt запись имеет «Опубликовано», читатель CLIENT не видит «Черновик». Фуксиевое авторское короткое послание — текст, не кнопка.
7. **DIARY-MEDIA.** Опубликовать отдельную заменимую запись с картинкой/аудио, записать bytes для бинарной передачи и отдельную verification. Во время server verify не должно быть фиктивных «0/0 байт» как будто никакой операции нет. Проверить опубликованную ревизию и независимую новую рабочую редакцию.
8. **CATALOG MODULE.** В MASTER локально собрать тестовый модуль «Индукция Элмана» с 3 реальными различимыми аудиофайлами и небольшой паузой, опубликовать **отдельной технической операцией** `Добавить в каталог`. Сервер receipt подтверждает точный contentId/revision/files, а не просто «В очереди». Каталог сам по себе не создаёт дневниковую запись.
9. **CATALOG PROGRAM.** Из существующего template (=Программа) создать программу, содержащую модуль и 3 трека, и опубликовать. Сохранить внутренние template IDs. Проверить также категорийный ввод: `Индукция` и `индукция` не создают новые дубли; существующие связи не уничтожаются. Поля карточки удерживают фокус, автор/правообладатель подставляется из редактируемого профиля.
10. **CATALOG CLIENT.** На втором телефоне CLIENT26 (только update поверх CLIENT25, если допустима проверенная подпись, иначе STOP) войти под другой реальной Google identity. `Библиотека → Облачный каталог` показывает разрешённый module/program. Попытка CLIENT опубликовать — серверный deny. Установка скачивает exact dependency graph и все 3 аудио; при повторе нет дублей и лишних загрузок. Отключить интернет и вручную прослушать все 3 трека в сессии/плеере. Если пользователь не может физически подтвердить звук — NOT_RUN, не PASS.
11. **CONTENTLINK.** В MASTER создать отдельный дневниковый анонс с реальной ContentLink на опубликованный модуль/программу. CLIENT видит install action только при валидной доступной ссылке. Для прежней записи «Индукция Элмана вариант 2» без ContentLink краткий текст «Добавь себе в библиотеку» не должен неожиданно становиться кнопкой. Проверить wrong revision/withdrawn/permission denied — явное сообщение, не пустое действие.
12. **RETRY/RESTART.** Для тестовой очереди временно прервать сеть, свернуть/развернуть Android, нажать Pause/Continue, повторить проверку права. Не должно появиться дублей контента/задач/байтов; при утерянном ответе клиент сначала уточняет commit. При ручном выходе задача не пересылается под другим account. Вверху глобальный статус передач жёлтый и открывает правильную задачу.
13. **STORAGE REGRESSION.** После обычного обновления сравнить локальные треки, модули, программы, историю, diary drafts, порядок, паузы и hashes заменимых media. Приложение не должно показывать пустую базу вследствие silent reset/GC. Если недоступно проверить отдельный исторический случай, статус PARTIAL, не придумывать восстановление ранее потерянных объектов.

## Минимальный акт приёмки

- Имя APK/package/versionCode/cert SHA (без секретов), телефон A/B, дата и версия Android.
- Результаты 13 пунктов с подтверждением реальных app screenshots/моментов и traceId/codes (без личных данных).
- `AUTH` физически PASS ≠ `CATALOG INSTALL` PASS. Указать отдельно `Code`, `Emulator`, `Live GAS/Drive`, `Owner device`.
- При STOP-SHIP не просить удаление приложения, запретить подмену доказательств автоматическими тестами.
