# Доставка авторского дневника

Статус: клиент, локальные черновики/кеш и тестируемый HTTPS адаптер реализованы. **Живой сервер и авторская авторизация BLOCKED: адрес и инфраструктура не предоставлены.** В обычном APK нет авторских кнопок и встроенных токенов. Опубликованных материалов в исходниках нет; приложение показывает честное пустое состояние.

## Настройка сборок

- Читатель: `flutter build apk --debug --dart-define=SULFI_DIARY_API=https://ВАШ_СЕРВЕР/v1`.
- Рабочее место владельца: тот же URL и `--dart-define=SULFI_AUTHOR_WORKSPACE=true`. Это отдельная конфигурация для автора, а не платная роль. Без URL доступны только местные черновики/предпросмотр. В публичную сборку флаг не включать.
- В рабочем месте автора кнопка ключа принимает краткоживущий bearer token, выданный **вашей системой входа**. Клиент проверяет права через `/author/me`. Токен только в памяти процесса, не в SQLite/preferences/логах/APK. Не передавать refresh token, пароль почты или ключ service account. Logout/закрытие процесса требует нового входа. Отдельный интерфейс получения токена и выбранный провайдер входа требуют развёртывания сервера; это не имитация готового Google входа.
- HTTPS обязателен, redirect отключён. В API отправляется только авторский текст. Аудиофайлы, темы, история и заметки клиента не входят в контракт.

## Контракт API v1

`GET /v1/public/entries?since=REVISION&page=CURSOR&limit=50` — без токена, только опубликованные записи:

```json
{"entries": [{"id":"stable-id","version":1,"number":1,"message":"Послание","body":"Текст","createdAt":"2026-11-04T10:00:00Z","updatedAt":"2026-11-04T10:00:00Z","publishedAt":"2026-11-04T10:00:00Z","status":"published"}],"removedIds":[],"revision":"42","nextPage":null}
```

`since` — последний **полностью сохранённый** курсор ревизии; `page` — следующая страница того же неизменяемого снимка. Все страницы одной синхронизации должны иметь одну revision. Если курсор устарел, сервер должен восстановить полный набор изменений/снятий с него, а не молча вернуть неполный каталог. Публикации и tombstones выдаются в порядке актуальной серверной версии. Снятие публикации возвращает только ID в `removedIds`, без приватного текста. Клиент атомарно применяет весь набор страниц и новую revision; при сетевой ошибке/непубличной записи старый кеш и revision целы. Кеш не является механизмом срочного отзыва: офлайн-читатель хранит ранее опубликованное до следующей синхронизации.

`GET /v1/author/me`, `Authorization: Bearer TOKEN` → `{"canPublish":true,"expiresAt":"…UTC…"}`. Сервер проверяет подпись, issuer, audience, срок, allowlist владельца; одного поля, переданного клиентом, недостаточно. Без действительных прав 401/403.

`PUT /v1/author/entries/{encodedId}`, bearer + JSON:

```json
{"expectedVersion":1,"publish":true,"entry":{"id":"stable-id","version":1,"number":1,"message":"Послание","body":"Текст","createdAt":"2026-11-04T10:00:00Z","updatedAt":"2026-11-04T10:00:00Z","publishedAt":null,"status":"draft"}}
```

Сервер проверяет доступ/размеры, стабильный ID, `expectedVersion` в транзакции, назначает новую монотонную version и собственное время; возвращает `{"entry": ...}` со статусом `published` и непустым publishedAt либо `unpublished` при publish=false. Конфликт версии 409/412, не перезаписывать автоматически. Черновой контент хранится в закрытой авторской коллекции, публичная выдача читает только published-проекцию. **Никаких общедоступных write endpoints.**

## Перед живым включением

Google Drive/Apps Script допустим только с проверяемой авторизацией владельца на записи; анонимная публикация запрещена. Затем проверить 401/403, конфликт версии, несколько страниц, повтор запроса, публикацию/снятие и обновление на втором телефоне. Настроек и токенов сейчас нет, сервер не развёрнут и никакие личные материалы не публиковались.
