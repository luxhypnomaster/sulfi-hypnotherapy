# Дневник: авторские действия внутри «Сульфи»

Актуально для 0.4.3+8. Заменяет отдельную авторскую сборку и ручную вставку токена.
Создание, автосохранение, предпросмотр, сохранение на Диск, публикация и снятие —
в приложении. ChatGPT не является посредником публикации. Редактировать код Apps
Script на телефоне не нужно.

**BLOCKED: живой вход и публикация требуют Google OAuth-конфигурации и развёртывания
сервера.** Код и тесты подготовлены; сервер в аккаунте владельца не установлен.

## Приложение

- Читатель открывает оглавление и кеш без входа. Видит только публикации.
- Кнопка «Войти как автор через Google» вызывает штатный выбор аккаунта. Редактор
  и черновики открываются владельцу; сервер отдельно проверяет Google ID token.
- После входа локальное редактирование работает при недоступном сервере. После
  перезапуска процесса требуется вход заново; роль и токен в БД не сохраняются.
- «Сохранить черновик» сохраняет на телефоне, «Сохранить на Диск» — на сервере.
  Правки опубликованного текста остаются приватными до повторной публикации.
- Загрузка с Диска добавляет отсутствующие ID. Существующие местные тексты не
  заменяются. Отдельный UI разрешения межустройственного конфликта ещё предстоит.
- Снятие публикации оставляет текст у автора; читатель получает только ID удаления.
  Офлайн-кеш отзывается при следующей синхронизации.
- Выход скрывает черновики и очищает сеанс, но не удаляет SQLite. Аудио, темы и
  история вообще не входят в запросы. Паролей, refresh tokens и ключей в APK нет.

## Конфигурация для разработчика

Один APK, два **несекретных** значения:

```sh
flutter build apk --debug \
  --dart-define=SULFI_DIARY_API=https://script.google.com/macros/s/DEPLOYMENT_ID/exec \
  --dart-define=SULFI_GOOGLE_WEB_CLIENT_ID=WEB_CLIENT_ID.apps.googleusercontent.com
```

Обозначения выше не являются настоящими настройками. Без client ID вход сообщает
об отсутствии настройки; чтение кеша/аудиофункции остаются доступны. Прежний
`SULFI_AUTHOR_WORKSPACE` не используется. `script.google.com/d/PROJECT_ID/edit`
является ссылкой редактора, а не API endpoint. Нужны Web OAuth client ID (audience),
Android OAuth client для `ru.sulfi.sulfi_hypnotherapy` и SHA-1 фактической подписи.
Нельзя создавать новый signing key вместо установленного без плана миграции.
Не просить у владельца пароли, одноразовые коды или callback URL с OAuth-кодами.

## Сервер Apps Script / Drive

Исходники: `server/google_apps_script/`. V8 web app исполняется от владельца,
общедоступен только `GET public/entries`. Авторские операции проверяют RS256,
issuer, точный audience, exp/iat/nbf, verified email и allowlist владельца.
Закреплена MIT-библиотека jsrsasign с V8-адаптером, сертификаты Google кешируются.
Подробности токена и тексты не возвращаются в диагностике.

Script Properties, задаваемые разработчиком:

| Свойство | Значение |
| --- | --- |
| `SULFI_GOOGLE_WEB_CLIENT_ID` | Тот же настоящий Web client ID, что в APK |
| `SULFI_AUTHOR_EMAIL` | Подтверждённый email владельца |
| `SULFI_DIARY_FOLDER_ID` | Выделенная закрытая папка дневника |

Используется только выделенная папка. Shared/public папки и файлы отвергаются.
Google scope Drive широкий на стороне сервера; Android запрашивает только вход,
без Drive scope. Анонимное чтение не создаёт файлы. Дубликат/повреждение state
вызывает ошибку, а не сброс. Исходный каталог пользователя не перезаписывается.

Хранилище MVP — закрытый `sulfi-diary-state-v1.json`, до 2 MB. Рабочие тексты и
опубликованные снимки раздельные. Запись под ScriptLock с expectedVersion,
серверными номером/временем/версией. Лимит тела — 400000 UTF-16 единиц, послания —
1000; при превышении запись отклоняется без изменения данных. Для большого каталога
нужен другой store с тем же контрактом. Квоты Apps Script не позволяют обещать
неограниченный публичный сервис.

Перед установкой экспортировать существующий проект вне Git, проверить код,
загрузить исходники, настроить OAuth/свойства и создать версию web app. Включённый
Apps Script API НЕ даёт автоматически OAuth-доступ к projects/deployments.
В текущем окружении экспорт существующего проекта прочитан и сохранён. Инструмента
управления Apps Script/его OAuth-авторизации нет, код/деплой не изменялись.

## Контракт

- `GET public/entries?since=REVISION&page=CURSOR&limit=50`
  → `{entries,removedIds,revision,nextPage}`, только published. Курсор привязан
  к revision, изменение между страницами даёт 409. Клиент применяет весь набор
  атомарно. Tombstones сохраняются; future since отклоняется.
- `GET author/me`, bearer → `{canPublish:true,expiresAt}`.
- `GET author/entries?page=CURSOR&limit=50`, bearer → `{entries,nextPage}`.
  Это закрытые рабочие тексты; курсор привязан к mutation revision.
- `PUT author/entries/ID`, bearer, `{expectedVersion,entry}` → `{entry}`:
  сохранить рабочий текст, не меняя опубликованного снимка.
- Та же операция с `publish:true/false` — опубликовать/снять. 401/403 без прав,
  409 при конфликте. Поля server ID/номер/время/версия не подменяются клиентом.

Обычный HTTPS backend сохраняет Bearer/PUT и не следует redirect. Для Apps Script
адаптер упаковывает авторский запрос в POST JSON `{method,route,query,token,body}`.
ContentService отвечает `{status,data}`. Допускаются до трёх 302/303 только на HTTPS
`script.googleusercontent.com:443`, отдельным GET без токена/тела. Login/сторонние
URL отвергаются. Публичное GET без токена. Есть таймауты и лимит ответа 2 MiB.

## Проверки и приёмка

```sh
node --test server/google_apps_script/test/backend.test.mjs
flutter analyze --fatal-infos
flutter test --reporter expanded
```

Node/OpenSSL используют настоящие независимо созданные RSA-подписи и X.509; Google/Drive/Apps
Script API подставлены. Flutter использует подставной identity и HTTP-сервер.
Живые SDK/Consent Screen/Drive permissions/квоты/web app/телефон этим не проверены.
После настройки нужны реальные вход владельца/чужого аккаунта, отказ сети/отмена,
черновик → публикация → чтение вторым телефоном → снятие, истечение токена,
конфликт версии и обновление APK поверх старого без потери данных.
