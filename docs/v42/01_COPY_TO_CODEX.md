# СУЛЬФИ — ТЕКСТ ЗАДАНИЯ CODEX НА НЕМЕДЛЕННОЕ ИСПРАВЛЕНИЕ

Исправь **существующее** Flutter/Android-приложение «Сульфи — Самогипноз» по приложенному пакету **v4.2**. Этот пакет дополняет и при наличии конфликта заменяет полученные ранее v4.0/v4.1. Не создавай новую кодовую базу. Не меняй утверждённые художественные референсы и не заменяй их придуманными картинками.

**Критически важно: прежний запрет «не реализовывать дневник» был ошибкой составителя задания и ОТМЕНЁН. Реализовать авторский дневник Сульфи для обычного MVP — обязательная задача. Исключены только платные роли, Professional, ИИ и иные будущие возможности.**

1. Прочитай `00_READ_FIRST.md`, `02_REQUIREMENTS_FULL.md`, `03_ACCEPTANCE_TESTS.md`, `04_CONFLICTS_AND_ASSETS.md`, затем существующие репозиторные `AGENTS.md`, спецификации и реальный код.
2. Перед изменениями создай рабочую ветку, зафиксируй версию и сделай короткий аудит текущего состояния. Не удаляй аудио, журналы, шаблоны и локальные данные. Не пушь прямо в main и не переписывай существующее приложение.
3. Приоритет P0: восстановить перетаскивание, компактный редактор фаз/модулей, одну паузу с золотыми часами, выбор аудио касанием строки, исправить плеер согласно `PLAYER_FINAL_APPROVED_9x16.png`, сделать корректный конец сеанса → История, исправить выбор категории «Установки» при создании своей записи.
4. Приоритет P1: уплотнить экран шаблонов, стартовый экран, диктофон без лишней прокрутки; восстановить/реализовать **дневник** (оглавление, чтение, редактор, черновики, публикационные статусы и безопасный путь облачной доставки).
5. Делай изменения малыми завершёнными этапами, после каждого запускай доступные тесты/анализ/сборку. Веди `reports/v4_2_AUDIT.md`, `reports/v4_2_IMPLEMENTATION.md`, `reports/v4_2_TESTS.md`, записывай реальные коммиты.
6. Важно: не выдавать личные записи за общие; не публиковать черновики; не прятать секреты облака в APK; не симулировать завершение/воспроизведение/успешную публикацию.
7. Если нет credentials для живой публикации — **всё равно реализуй локальную пользовательскую часть дневника, API-контракт, защищённый адаптер и тесты**, а настройку/развёртывание сервера честно обозначь `BLOCKED: требует авторизации/конфигурации`. Не исключай всю функцию.
8. В конце предоставь build APK (если SDK доступен), PR/коммиты, перечень реализованных сценариев, скриншоты реального Flutter-рендера (если возможны), результаты `flutter analyze`, `flutter test`, `flutter build apk --debug` и список оставшихся блокеров.

**Не останавливайся на пересказе ТЗ или плане. При доступном репозитории переходи к исправлению кода и тестам.**
