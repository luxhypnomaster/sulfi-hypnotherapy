# СУЛЬФИ v4.2 — ЕДИНОЕ КОРРЕКТИРУЮЩЕЕ ТЗ ПО ПРОВЕРЕННОЙ СБОРКЕ

Дата: 04.11.2026. Источник: замечания владельца по реальным Android-скриншотам `2234–2254` и утверждённые документы/референсы v4.0/v4.1.

## 0. Неизменяемые общие принципы

- Flutter/Android, действующие модели `Фаза → Модуль → Трек` с отдельными паузами и возможностью повторного использования. Сохранить историю, миграции, реальные аудиофайлы, записи, шаблоны, идентификаторы, actual timeline и frozen plan.
- Различать **каталог модулей** (definitions) и независимые **экземпляры модулей** внутри сессии: правка экземпляра не должна менять каталог автоматически. Фазы можно повторять; нельзя навязывать фиксированную уникальность.
- В рабочих экранах главный приоритет — **плотность информации и скорость операций**, затем декор. Стиль: чёрная кожа, золото, фуксия, яркий зелёный; размер текста читаемый, интерактивные области не меньше ~44–48 dp.
- Соблюдать Android SafeArea, экранную клавиатуру, крупный шрифт, различную высоту экранов. **Не делать статические картинко-кнопки**, данные реальные, состояние движка синхронизировано с UI.
- Не вводить Professional, ИИ, платные роли, маркетплейс, гипнотическую диагностику или новую навигацию по колбе для Pro.

## P0-01. Диктофон: компоновка и категория «Установки» (2234.jpg)

**Проблема:** планшет и рабочая форма опущены, экран требует прокрутки до нижних действий; у новой записи нельзя выбрать «Установки». На приложенном скриншоте также состояние «Запись завершена» при `0:00` с сообщением об остановке из-за прерывания — проверить это как отдельный edge case.

**Должно стать:**
- Поднять рабочую кожаную область, уменьшить декоративные отступы, сделать так, чтобы типовые поля, запись и кнопки `Отмена` / `Сохранить трек` были доступны на стандартном Samsung без прокрутки при закрытой клавиатуре. При маленьком экране/крупном шрифте допускается контролируемая внутренняя прокрутка — без перекрытия кнопок.
- Сохранить утверждённую композицию диктофона `RECORDER_APPROVED.png`: спираль, настоящая запись и таймер, безопасные действия паузы/прослушивания/завершения; никаких декоративных имитаций.
- Модель трека обязана отдельно хранить **происхождение** (`bundled/imported/recorded`, в UI `Общие`/`Мои`) и **содержательную категорию** (`Подготовка`, `Индукция/Погружение`, `Углубление`, `Безопасное место`, `Проработка`, `Интеграция`, `Прогрессия`, **`Установки`**, `Выход`, `Другое` и т.п.). Категория — метаданные и фильтр, НЕ жёсткая привязка аудиофайла к месту в сессии.
- При создании/редактировании собственной записи разрешить выбирать категорию **`Установки`**. Такая запись одновременно видна в `Мои` и через представление/фильтр `Установки` (не взаимоисключающие вкладки).
- В настройках не заставлять пользователя выбирать «общий» статус для личной записи. `Общие` не означают автоматически публичную загрузку личного файла.
- Состояние `0:00`, прерванная/пустая запись: недопустимо сохранять пустой/битый аудиофайл как успешный; показать понятное восстановление/отмену. Сохранить полноценную непустую запись после interruption, если файл действительно валиден.

## P0-02. Один тип «Пауза», без меню «Тишина / Самостоятельная работа» и без описания (2236.jpg, 2238.jpg)

**Проблема:** пользователь сначала выбирает ненужные два режима, затем получает стандартный диалог со значением секунд `60` и полем «Описание» вместо утверждённых золотых часов.

**Должно стать:**
- Действие редактора: **`+ Добавить паузу`**. Никакого промежуточного меню `Тишина`/`Самостоятельная работа` для новых вставок. Одна сущность `Пауза` для пользователя, вставляемая в любое место среди треков и модулей.
- Открывать **полноэкранный фирменный редактор времени** по `PAUSE_CLOCK_APPROVED_REFERENCE.png`: золотые карманные часы/глаз и **две независимые крутилки минут и секунд**, редактируемое `MM:SS`, `Обнулить`, `Применить`/`Отмена`, безопасная обработка 0. Поле `Описание` полностью убрать; простой системный диалог секунд исключить.
- Сохранить расчёт общей длительности без двойного учёта, часы реально управляют значением. Сохранить, если уже реализовано, различие внутренних данных `delayBeforeMs` (задержка **перед** элементом) и самостоятельной паузы как очередного исполняемого элемента: **не склеивать без миграции**, но не выводить пользователю лишние технические режимы.
- Старые `Silence/FreeWork` записи мигрировать/отображать как `Пауза` без потери времени, относительного порядка и истории. Если в старых данных есть пауза без фиксированной длительности, корректно поддержать ручное окончание или явно предложить пользователю задать время без молчаливого удаления. Не ломать импорт старых шаблонов.
- Пауза 0 — определённое поведение (обнулённая длительность; для ручного завершения только если явно предусмотрено логикой). Не считать ноль автоматически 60 секундами.

## P0-03. Компактность и перетаскивание в редакторе **модуля** (2236.jpg)

- Любая строка модуля — трек либо пауза — занимает минимально необходимую высоту. Название, продолжительность и неброские действия; без огромных пустот.
- **Long-press drag & drop:** зажать любой элемент и переместить в начало, середину, конец; перетаскивать между разными типами элементов в одном общем порядке. Допустим видимый `grip` как точка начала захвата; фактическая жестовая область должна быть удобной. Обычный тап не должен случайно запускать перенос.
- Изменение порядка реально меняет последующее воспроизведение, сохранённый экземпляр и динамическую длительность. IDs не заменять индексовыми псевдо-ID. Поддержать прокрутку во время перетаскивания.

## P0-04. Компактный редактор структуры **сессии** + reorder (2242.jpg, 2246.jpg, 2248.jpg)

**Проблема:** внутри фазы четыре крупные команды занимают почти весь экран; карточки огромные; элементы перестали перемещаться долгим удержанием. Низ заполнен бесполезными дублирующими действиями.

- На каждом уровне — плотные строки высотой ориентировочно 48–56 dp с возможностью аккуратно раскрыть подробности. **Сжать вертикальные отступы**, а не уменьшать шрифт до нечитаемого. При раскрытии фазы вместо четырёх громоздких команд — одна компактная `+ Добавить`, открывающая меню `Модуль / Трек из библиотеки / Пауза / Записать свой трек`. Аналогично компактное добавление внутри модуля.
- Фазы, включённые в план, можно **перетаскивать в общем порядке**. Внутри фазы в единой последовательности свободно перемещаются модули, отдельные треки и паузы; внутри модуля — все треки и паузы. Не обрывать drag на границах прокрутки. Фиксировать порядок в модели, сохранять через выход/возврат и после перезапуска.
- Управление раскрытием: справа в том же месте всегда `+` в свёрнутом состоянии и `−` в раскрытом. Касание заголовка тоже раскрывает/сворачивает. **Никогда не подменять `−` значком `⋮`.** Если контекстное меню действительно нужно, показывать его отдельной кнопкой внутри раскрытой области, не поверх области `+ / −`.
- Не смешивать обычный тап `раскрыть`, long-press `перетащить`, отдельный тап `контекст`.
- Нижняя панель: **ровно три компактные кнопки в одном закреплённом горизонтальном ряду**, с короткими подписями `Выбрать` (другой шаблон), `Сохранить` (как шаблон), `Применить` (изменения и возврат). Полные названия показать через доступность/подсказку; в landscape/узком экране обеспечивать доступность.
- **Полностью убрать только из нижней панели редактора:** `Библиотека`, `Записать свой трек`, `Вернуть из шаблона`. Сами функции не удалять из приложения; выбор аудио/запись доступны в действиях соответствующего элемента фазы или модуля.
- Прокручивается список фаз, а не низ. Не допускать несохранённых изменений при выборе другого шаблона без подтверждения. `Применить` не запускает сессию.

## P0-05. Выбор аудио — **тап = добавить**, компактный список (2244.jpg)

**Проблема:** одна карточка трека почти на половину экрана, кнопка «Добавить в сессию» мелкая и отдельная, шапка занимает слишком много высоты. Каталог превратился в экран редактирования вместо инструмента выбора.

- В режиме `Выбрать аудио` каждая строка: название (1–2 строки), компактная категория, длительность, маленькая **отдельная кнопка прослушивания**. Без файла `MP3/МБ` в каждой строке, без `⋮`, без отдельной кнопки `Добавить в сессию`.
- **Обычный тап по строке мгновенно добавляет** трек в текущую выбранную фазу/модуль, без подтверждения и не запускает прослушивание. Касание отдельного play только слушает и не добавляет. Каталог **остаётся открыт**, чтобы можно было добавить следующую запись; показывается ненавязчивое `Добавлено`. Повторное добавление того же трека разрешено.
- Верхняя часть: минимальный заголовок, поле поиска, компактный выбор источника (`Все / Общие / Мои`) и категория-фильтр (в т.ч. `Установки`). Импорт звука — маленькое действие в header, НЕ огромная CTA.
- Целевые строки ~48–56 dp, ориентир **10+ доступных записей** в видимой части типового Android-экрана с учётом разрешения/масштаба текста. При длинных названиях корректная обрезка/раскрытие, доступность.
- Применять именно в сценарии добавления. В **обычной библиотеке управления файлами** можно оставить отдельные действия просмотра, редактирования, удаления и метаданных; не спутать эти два режима.

## P0-06. Активный плеер — художественное соответствие + настоящая работа элементов (2250.jpg)

**Проблема:** нынешний UI визуально сильно отличается от утверждённого; колба нарисована узкой вертикальной полосой, большие золотые часы отображаются скорее картинкой, исчезли кнопки предыдущего/следующего трека **на самих часах**, круговая шкала не умеет перематывать. Главная нижняя кнопка выглядит жёлтой.

- Строго ориентироваться на `assets/approved/PLAYER_FINAL_APPROVED_9x16.png`. НЕ использовать другие изображения плеера, в том числе экспериментальную пару экранов и коллажи. Перерисовывать замысел и делать новое художественное предложение не нужно. Сохранять узнаваемую цельную композицию: полноценная алхимическая колба слева (огонь, золото, светящийся раствор), золотые карманные часы с глазом справа, фуксия активного этапа, верхний блок времени, три пары навигации и краткая карточка.
- Колба **заполнена в начале и уваривается в течение всей сессии**. Уровень уменьшается по реальному общему прогрессу, в т.ч. аудио и паузам, а не зависит от количества строк. Не сжимать колбу в полоску и не брать арт, содержащий динамический текст, как единый полноэкранный растр.
- Структура по шкале: **Фаза 1 в самой верхней доступной позиции**; все фазы и названия модулей видны в порядке сверху вниз, **только активная фаза раскрывает треки всех своих модулей**. По завершении фаза схлопывается; раскрывается следующая. Прокручивается лишь навигационная шкала, с авто-выведением текущего пункта в зону видимости. Не навешивать самостоятельные неподтверждённые функции Professional (тап по шкале для перехода к модулю в Pro — не задача MVP).
- Часы — **реальный управляемый мини-плеер**: внутри `← трек`, `play/pause`, `трек →`, `elapsed/total`, живой progress ring и **круговая перемотка по жесту на ободке**. Круговая шкала обязана задавать позицию конкретного трека, поддержать касание/перетаскивание с правильной геометрией и обновлением аудиодвижка. Нельзя подменять её единственным отдельным линейным слайдером. Во время интервала отображать соответствующее состояние, не позволять искать несуществующий аудиофайл.
- Три нижних пары: предыдущий/следующий **трек**, **модуль**, **фаза**; все действуют на текущий `SessionRun`, синхронизируют состояние и журнал. Необходимо защититься от двойных нажатий и ложных переходов.
- Основная кнопка — **«Закончить сеанс»**, **ярко-зелёная, не неоново-жёлтая** (ориентир зеленого #A6FF2E, уточнять на реальном устройстве), ширина в пределах двух кнопок над ней. Надпись «Время трансформации» — фуксия. Устаревшую подпись «Завершить сессию» не использовать.
- **Нажатие «Закончить сеанс»**: подтвердить действие; если настроен безопасный выход, позволить `Перейти к выходу` (не считать сессию оконченной до его завершения) либо `Закончить сейчас`; `Отмена` оставляет исполнение. При явном досрочном окончании остановить движок, сохранить actual timeline и статус `Прервана` и **открыть «Историю»**. При штатном завершении последнего элемента сохранить статус `Завершена` и **тоже автоматически открыть «Историю»**. При входе в историю показать сохранённую сессию, не пустой список. Не терять пройденный путь и не считать пропущенное проигранным.
- Убрать визуально лишнюю дублирующую полоску перемотки при наличии работающей круговой шкалы на часах, если она портит утверждённую компоновку. Если линейная шкала сохраняется для accessibility, она вторична, не заменяет основную.
- Проверить реальную работу на разной высоте экрана, со шрифтом 120–150%. Не принимать static PNG вместо интерактивных виджетов и не утверждать сходство без **скриншотов реального Flutter-экрана**.

## P1-07. Список шаблонов — вместо огромных карточек плотные строки (2254.jpg)

- Вместо «продающих» пустых полотен сделать обычный компактный каталог: `название | краткий состав | длительность | контекстные действия`. Ориентир ~56–72 dp на обычную запись с двумя строками; предупреждение «завершающий трек не настроен» — отдельный компактный статус, не большая рамка.
- Тап на строку **сразу выбирает** шаблон (из главного экрана либо текущего редактора с подтверждением потери незаписанных правок), **не нужна огромная кнопка «Выбрать»**. Отдельное `⋮` справа — переименовать/редактировать/удалить (с подтверждением удаления), не мешает обычному выбору.
- Действия создать шаблон / из текущей конфигурации сократить до одной верхней компактной панели, поиск оставить. На типовом экране должно помещаться несколько (ориентир 7+) пользовательских шаблонов без бессмысленных пустот.
- Полноэкранные описания назначения программы — только в будущем отдельном детальном просмотре, НЕ как обязательный размер каждой строки каталога.

## P1-08. Главная перед началом — уплотнить сведения, не обрезать название (2252.jpg)

- Убрать избыточный статус `№3 · До старта` в отдельной строке: номер и состояние уместить компактно рядом с заголовком/темой или в маленький статус, если действительно нужны. `До старта` как отдельная крупная надпись не нужна.
- Дата/время в одной строке. Длинное название показать читабельно (макс 2 строки с возможностью открыть полное название/изменить), а не одной нелепой обрезанной полосой.
- Уменьшить неинформативные отступы, сохранить полезную высоту для полной ширины структуры сессии и компактной карточки активного шаблона.
- Сохранить утверждённый портрет Сульфи и общий стиль, кнопку `НАЧАТЬ ТРАНСФОРМАЦИЮ`, четыре нижних навигационных действия (не придумывать пятую кнопку без необходимости).

## P1-09. Авторский «Дневник Сульфи» — **ОБЯЗАТЕЛЬНАЯ функция MVP**

**Критическое исправление ранее ошибочного задания:** в ночном v4.1 было написано `не реализуй дневник`; пользователь этого НЕ утверждал. **УКАЗАНИЕ ОТМЕНЕНО.** Исключёнными остаются платные роли, Professional и ИИ; дневник обычной версии делать.

### Назначение
Это **авторские записи/послания Сульфи для читателей приложения**, НЕ дневник клиента, не персональные медицинские записи, не соцсеть и не галерея изображений. Два отдельных поля: `Короткое послание` (фуксия, может выводиться на главной и ведёт к записи) и `Основной текст`.

### Внешний вид — без придумывания нового стиля
Чёрная кожаная папка/планшет, золотой верхний зажим, тонкое перо сбоку, лист состаренной бумаги, читабельный текст, аккуратные алхимические украшения. Портрет Сульфи **не требуется** на страницах дневника. Отвергнутые коллажи и изображения личного дневника не использовать. Поскольку финальные PNG редактора и оглавления ещё не утверждены, Codex должен реализовать **консервативный рабочий UI в пределах уже существующего стиля**, не блокируя функцию из-за отсутствия художественного постера. Не создавать произвольных больших карточек или декоративных галерей.

### Минимально законченный функционал
1. **Оглавление**: опубликованные записи в обратном хронологическом порядке, короткое послание/заголовок, дата, переход к чтению. Компактный список, локальный кеш, понятные состояния пусто / нет сети / ошибка, обновление.
2. **Читатель**: номер/ID, день недели/дата/время на **первой странице**; короткое послание фуксией + текст. Если длинный текст — разбиение на страницы по реальной доступной высоте, не фиксированным символам; следующие страницы только продолжение текста, внизу `N из M` + назад/вперёд. Кнопки возврата на главную и к оглавлению. Нижняя символика: ouroboros с алхимическим знаком серы 🜍, без символов Люцифера.
3. **Авторский редактор**: отдельные поля короткого послания и полного текста, создание/редактирование, черновик, предпросмотр в точном формате читателя, публикация/снятие публикации, защита от потери введённого текста. Черновики видит только автор; обычным читателям недоступны кнопки авторского редактирования.
4. **Модель данных**: стабильный ID, версия/updatedAt, createdAt/publishedAt, статус `draft/published/unpublished`, порядковый номер/slug при необходимости, поля контента; локальное хранение и миграция без потери. Если на главной есть короткое послание — оно открывает соответствующую опубликованную запись; оно может обновляться вместе с каталогом.
5. **Облачная публикация**: цель — автор централизованно публикует, читатели получают обновления и продолжают читать закешированное офлайн. Обсуждавшаяся технология Google Drive + Apps Script **допустима**, но не является запретом на безопасный равноценный backend. Нельзя встраивать секрет авторизации в APK, открывать публичный write endpoint без auth или считать локальный черновик уже публичным. Разделить аутентифицированное создание/обновление и публичную проверенную раздачу опубликованных записей, с версионированием, пагинацией или incremental sync.
6. **Отсутствующие секреты/деплой**: реализовать в приложении модели, экраны, локальную работу, сетевой интерфейс и тестируемый адаптер; подготовить документы настройки cloud/backend. Реальную серверную публикацию объявлять `BLOCKED` до предоставления credentials, доступа и выбранного безопасного способа авторизации. Не откладывать **весь** дневник из-за этого. Не придумывать настоящие облачные URL и не публиковать приватный черновик на тестовом общедоступном адресе.
7. **Навигация**: дневник доступен с главного экрана через небольшой встроенный блок послания/перехода либо существующий согласованный пункт, **не заменять без согласования четыре основные кнопки нижней панели**. Не превращать экран в персональную записную книжку пользователя.

### Приёмка дневника
- Создать черновик → закрыть → открыть → данные целы.
- Предпросмотр совпадает с чтением; страница `N из M` меняется, длинная запись читаема.
- Опубликовать в безопасном авторском режиме → запись видна обычному читателю после получения данных/кеша.
- Снять с публикации → после синхронизации запись исчезает из публичного списка, а локальные личные черновики сохраняются.
- Пользователь без авторских прав не видит и не читает чужие черновики, не может вызвать API публикации.
- На отсутствие сети публичное чтение закешированного не падает.

## P2-10. Сквозные требования к визуальной и функциональной приёмке

- Обязательно проверить на реальном Flutter-рендере, а не сравнивать скриншот макета сам с собой.
- Плотность UI: экраны списка — 10+ треков и 7+ шаблонов при типовых размерах/масштабе, если позволяют доступные высота и количество данных; интерфейс не должен ухудшать доступность.
- Кнопки отображают состояние, которое действительно исполняют; disabled не маскирует ошибки навигации. Любое `0:00` в записи/паузе обрабатывается явно.
- В логах нет секретов, персональных данных или внутренних путей пользователя. Отчёт по фактическому тестированию, без фиктивных PASS.
