## 4. B — K-025. Локальное отличие копии от библиотеки (только редактор и старт)

- **Редактор структуры сессии:** библиотечный ModuleDefinition вставлен как PhaseChild-instance и локально изменён (вложенные шаги/порядок/паузы/типы/длительности/ID аудио/применимые параметры). Название такого реального модуля показать **красновато-фуксиевым + курсивом**. Показывать только если текущая копия **фактически отличается** от сопоставимой сохранённой версии библиотеки. Если действия Undo/восстановление вернули полное семантическое совпадение — убрать индикацию. Смена самой библиотеки не должна ложно скрывать отличие старого экземпляра; использовать корректный source ID/version/fingerprint, если они доступны, и документировать legacy без происхождения.
- **Стартовый/главный экран:** название активного выбранного шаблона по тому же правилу: фактический composition/draft отличается от закреплённого библиотечного шаблона → красновато-фуксия + курсив; обратно совпало → стандартный стиль. Сравнивать состав (фазы, шаги, порядок, паузы, источники), а не просмотр, прогресс, историю или факт открытия редактора. Создание самостоятельного сохранённого объекта должно обновлять сравниваемый эталон по существующим правилам выбора шаблона, не мутируя старую библиотеку.
- Сохранять отсутствие фальшивого «modified» для прямого трека без библиотеки, для unverifiable legacy и при редактировании только несущественного runtime/текстового состояния. Если строгий baseline неизвестен, честная нейтральная индикация лучше ложной.
- **Не вводить этот цвет на экране запущенной сессии RunScreen:** там фуксия/current, зелёный/completed и серый/disabled имеют приоритет; даже курсив RunScreen в текущем задании НЕ требуется.
- Реализовать одну функцию semantic equivalence/revision-aware comparison, переиспользовать имеющийся fingerprint, но проверить что изменение/обратный Undo корректно пересчитываются и отображаются. Никаких отдельных флагов «редактировался один раз».

## 5. C — K-012/013/014. Точечная переносимая выгрузка

Обязательно исследовать существующий `CapsuleService` (аудит №7 описывает ZIP schema 1, dependency list, SHA и rollback; могло измениться). **Единый валидный механизм**, который может сформировать и восстановить:

1. **Трек:** только выбранный AudioAsset + его bytes + metadata/revisions/digest + права/происхождение, без несвязанных личных файлов.
2. **Модуль:** выбранное определение/состав, порядок, паузы, ссылки на его реальные треки и **транзитивное замыкание** нужных звуковых байтов. Без дублирования одинакового blob при нескольких ссылках.
3. **Шаблон:** фазы, модули, прямые шаги/паузы, порядок, durations, ссылки и closure треков, работоспособность на другом устройстве после import. Не выгружать историю сеансов, дневник и личные заметки по умолчанию.

- Формат ZIP/манифест должен быть **версионированным**, с метаданными, точными IDs, ожидаемыми digest/размером, понятным scope и содержимым. При экспорте отсутствие файла — явная проверенная ошибка, не успешный пустой пакет. Preflight: проверка путей, UUID/IDs, duplicate, missing deps, циклы, version conflicts, path traversal, ZIP bomb bounded limits; integrity verification до commit.
- Импорт: preview плана, осознанное разрешение конфликтов/ID, инсталляция только отсутствующего, атомарный/восстановимый commit, rollback. Не перезаписывать существующий материал молча; импорт одной упаковки повторно должен быть идемпотентен.
- Добавить доступные из существующих карточек/меню действия экспорта выбранного трека, модуля, шаблона; не перегружать UI многоуровневыми настройками. Для неизменяемых official пометить экспорт в соответствии с реальными access rights, не заявлять копирайтный или платный доступ, которого нет.
- Сохранить старую капсулу и миграцию: старые schema/IDs импортируются как прежде. Не удалять работавшую whole-capsule backup схему.
- Если часть экспорта уже есть и тестируется — отметить VERIFIED EXISTING и сделать только отсутствующую видимую кнопку/целевой scope и регрессии.

## 6. D — K-015. Ревизии, происхождение, сохранение предыдущих данных

- Устойчивый ключ: `ContentKey(type,id)` отдельно от `RevisionKey(type,id,revision)` и ID вхождения трека/модуля в конкретную сессию. Не менять исторические ID без alias/migration; версия APK != версия материала.
- Опубликованная/установленная ревизия **immutable**; «обновить» = новая RevisionKey, с прежним manifest/digest и необходимыми blob, а не `REPLACE` старой. Публичные/официальные оригиналы нельзя незаметно менять через личный редактор.
- Личная копия = новый ContentKey и provenance parent `(id,revision)` при известных данных, локально независимая. Legacy provenance неизвестен → не выдумывать родителя. Immutable revision хранит exact dependency refs, не заменять их ссылкой на «latest» при открытии истории.
- Не требовать полного копирования одинаковых аудиобайтов; blob-store может дедуплицировать по hash, если реализован корректный durable ownership/ref tracking. SHA-256 — целостность, НЕ цифровая подпись издателя или право доступа.
- Миграции SQLite additive/safe с rollback/preflight и backward compatibility; migration tests из предыдущей schema, экспорт/импорт старых capsule fixtures и сохранность app_settings/diary_sync. Время активной сессии не мигрировать/не мутировать поверх playback. Ни одна новая модель не должна автоматически пересобирать завершённый SessionRun.
- Важная граница: завершённая история сегодня сохраняет snapshot+hash, но не гарантирует байты удалённого аудио. **Запретить дальнейшее молчаливое разрушение доступных старых зависимостей при новых установках**, но не обещать восстановить ранее удалённые записи; если retention-policy требует отдельного owner decision — защитить ссылки, задокументировать выбор и не удалять content.

## 7. E — K-016. Локальный каталог с выборочной установкой

**Рабочий первый этап — локальный/тестовый каталог, без сети и без настоящего облачного деплоя.** Каталог должен индексировать карточки **до скачивания/установки**, иметь описание/тип/ревизию/размер/набор зависимостей/происхождение, индикацию Installed vs Available. Поддержать фильтр type(track/module/template), details и кнопку «Установить» только для реальных доступных локальных fixtures/test source. Если нет реального backend, не писать «онлайн библиотека доступна».

- Манифест: versioned `ContentRevision`, exact deps `(type,id,revision,digest)`, `MediaDescriptor sha256,size,mime,duration`, install status, verified digest, optional publisher identity/reference; не путать publisher string и доверенную подпись.
- Resolver: рекурсивное замыкание exact versions, циклы, конфликт несовместимых версий, отсутствующие зависимости, dedupe хешированных байтов, dry-run расчёт новых файлов/размера, планирование до записи. Не скачивать все файлы каталога ради одного шаблона.
- Installer: `planned -> staging -> verify -> commit -> installed` плюс failed/cancelled/retry; безопасная остановка/restart/recovery после сбоя между файлами и SQLite, no orphaned rows/free path/traversal; source abstracted (`LocalCatalogSource` с fixture, будущий remote adapter **без фиктивного сетевого вызова**). Repeated install idempotent, manifest+blob validated before publishing to library.
- UI: в существующих стилях, карточки, выбор материала, состояние установки, ошибки, объём. Если внешнего backend нет, пометить «Доступные демонстрационные материалы»/тестовый каталог или держать feature flag для dev; не смешивать демо с реальным публичным контентом. Установленные треки используют существующий library/preview/player; не создавать второй аудиоплеер, не занимать audio focus во время установки.
- Авторизация и платные права НЕ реализуются через локальные флаги; будущий серверный provider и publishing/entitlement только описать контрактом в отчёте `API_AND_DATA_CONTRACT.md`, не разворачивать и не привязывать к пользовательскому аккаунту без отдельного разрешения.
- Если добавление всего каталога не успевает, приоритет: корректные scheme+resolver+selective installer+tests > красивый каталог UI; нельзя выдавать одни модели/кнопки без рабочей установки за DONE.

## 8. F — K-017. Ссылка из дневника на контент

- Согласовать с существующей `DiaryEntry`/`DiaryBlock` и внешним `diary_api` без правок live server. `ContentLink = {type(track/module/template), logicalId, exact revision + digest, action install/open}` — отдельный структурный тип действия/метаданных, **не** image/audio/text блок и **не** произвольный URL на ZIP.
- В локальном diary UI, если запись реально содержит такую ссылку, показать осмысленную команду «Посмотреть / Установить» и передать `ContentLink` в каталог: уже установлено → показать доступный материал, не установлено + есть доступный source → установить точный version, отсутствует/нет прав → честное сообщение, не фальшивый успех.
- Не нарушать serialization старых записей: unknown fields сохранять и игнорировать корректно; никаких публикаций на настоящий Apps Script без подтверждённого контрактного пути. Если сервер пока не способен хранить ContentLink, локальный путь + тесты + контракт в отчёте; публичную end-to-end публикацию помечать BLOCKED, а не DONE.
- В этом ТЗ **не** реализовать всю многомедийную ленту, роли редактора, ротацию, read/unread, инкрементальные обновления публикаций или OAuth — это отдельный цикл будущего дневника.
