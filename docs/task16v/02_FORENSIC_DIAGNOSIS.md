# G0 — Строго read-only разбор причины

1. Сохранить текущие Git ref/source SHA/CI/APK readback и архивы до любого изменения; развернуть изолированный worktree/ветку `hotfix/task16v-p0-data-preservation`. Отдельно отметить, что уже зарегистрированы несколько активных PR; main не менять.
2. Сопоставить исходный APK24 и APK25 по package, version, certificate, applicationId/build variants, app data directory, DB/file schema names, root paths, permissions, shared_prefs, Flutter application-support/documents dir, архивам/капсулам, импортам, .nomedia; проверьте release build flags и миграционные ветки, не только git diff.
3. Найти все стартап-кодовые пути `openDatabase`, `onCreate/onUpgrade`, `drop`, `deleteDatabase`, `deleteAll`, `reset`, `bootstrap`, `sync`, owner/account partition, local guest/master scope, filters, lazy library load, SQLite WAL/SHM, pending queue cleanup, orphan cleanup и любые асинхронные операции, делающие «пустой список» при ошибке чтения. Не ограничиваться каталогом: **трек, модуль, дневник** исчезли одновременно.
4. Особое внимание к новой SDK restore/refresh и привязке identity, добавленной №16-Б. Проверить, что после штатного обновления old guest/local items не становятся невидимыми из-за scope/sub фильтров и не присваиваются другому пользователю без проверки; не обходить изоляцию аккаунтов. Отделить локальные объекты от контентного облачного каталога и очереди синхронизации.
5. Перед любым recovery определить, что именно наблюдается: `DB_FILE_MISSING`, `DB_EXISTS_TABLES_PRESENT_ROWS_PRESENT_BUT_FILTERED`, `ROWS_ABSENT`, `PATH_CHANGED`, `SCHEMA_MIGRATION_ERROR`, `FILE_BYTES_MISSING_REFERENCES_PRESENT`, `UI_LOAD_EXCEPTION`, `ALTERNATIVE_ACCOUNT_SCOPE` или `UNKNOWN`. Для каждой версии приложить source paths, минимальный reproduction, redacted trace, доказательную уверенность. Никаких необоснованных «почему».
6. Проверить, не открылся ли каталог под другим workspace/profile/edition. Сохранить correctness server role MASTER/CLIENT и запрет клиенту читать чужие черновики.
7. Весь анализ живого телефона начинается с минимально-инвазивной инструкции владельцу, **только если данные невозможно воспроизвести**: например, скриншот Android «О приложении» (package/version) или экран пустого списка; ничего не удалять/не переустанавливать. Ни `run-as`, ни `adb backup`, ни debug console не обещать без проверки допуска release и процедуры чтения/согласия. Никаких реальных личных аудио/записей в CI или открытых отчётах.

**Выход G0:** `ROOT_CAUSE_16V.md` с таблицей фактов и гипотез, `DIFF_AUDIT_16V.md` с точными кодовыми путями, отдельные `SAFE_READONLY_DIAGNOSTIC.md` и план восстановления без destructive writes.
