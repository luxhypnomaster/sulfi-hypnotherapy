# Версии, релизы и безопасные откаты — «Сульфи — гипнотерапевт»

## Цель
Сохранять каждую проверенную версию приложения и её исходный код так, чтобы новые изменения не разрушали последнюю работающую версию. Пользователь проекта не обязан разбираться в Git: Codex должен объяснять все действия и готовить их к одобрению.

## Ветки
- `main` — стабильная ветка. Из неё создаются официальные релизы. Никаких незавершённых или непроверенных изменений.
- `develop` — интеграционная ветка для текущей разработки. Создать от `main` после добавления стартовых файлов.
- `feature/<short-name>` и `fix/<short-name>` — временные ветки для изменений, которые могут повредить работоспособность. Codex отправляет pull request в `develop`.
- После тестирования Codex предлагает pull request `develop` → `main`. Мердж и релиз требуют явного согласования с владельцем.
- Если для приватного репозитория недоступны GitHub branch protection rules в используемом тарифе, придерживаться этого порядка процедурно; не утверждать, что запреты настроены технически.

## Версии
- Семантические теги `v0.1.0`, `v0.2.0`, `v0.2.1`, `v1.0.0`.
- Первый релиз — только после рабочего Android-билда и тестирования библиотеки аудио.
- `pubspec.yaml`: поле `version: X.Y.Z+N`. `X.Y.Z` — версия для человека, `N` — целочисленный номер сборки Android; увеличивать `N` в каждом публикуемом обновлении.
- Для каждого релиза вести `CHANGELOG.md`: изменения, исправления, ограничения и как проверить.

## GitHub Releases / APK
- Создавать GitHub Release только из проверенного коммита `main`; выпускать соответствующий Git tag.
- При наличии SDK и корректной конфигурации добавить GitHub Actions: на pull request — анализ и тесты, на релизный тег — сборка Android APK, сохранение сборки как release asset. При ошибках сборки не отмечать релиз как готовый.
- Позднее настроить стабильную Android-подпись: ключ хранить отдельно и надёжно резервировать, секреты не включать в Git. Не менять `applicationId` / подписывающий ключ без явно согласованного плана миграции.
- Не публиковать личные аудиозаписи, голос Сульфи, сессионные записи, истории, API-ключи и keystore.

## Откаты
- Git хранит коммиты: при ошибке искать стабильный тег/коммит и применять `git revert` или переносить исправную реализацию в новую ветку. Не делать необратимый force push и не переписывать историю `main`.
- Важно: возврат к старому APK на Android поверх более нового обычно не является надёжным вариантом из-за `versionCode` и миграций данных. Предпочтителен **новый исправленный выпуск** с большим номером сборки.
- Перед выпуском проверять, что существующие пользовательские импортированные треки, шаблоны и записи не теряются после обновления. Для схемы БД применять обратносуместимые миграции, где возможно.
- По утверждённому заданию 4 резервная капсула — обычный читаемый ZIP без собственного шифрования; файл содержит личные записи, место и получателя выбирает пользователь. История Git и APK **не являются** резервной копией пользовательских записей.

## Критерий готовности релиза
- `flutter analyze` и `flutter test` завершились успешно (или ограничения явно отмечены).
- APK реально собирается для Android; подтверждена возможность установки, при наличии устройства — ручное тестирование.
- Проверены основные сценарии: воспроизведение, пауза, запись, выход, фон, замена/удаление аудио, миграция данных.
- Сохранены `CHANGELOG.md`, Git tag, release notes, APK (если сборка доступна), инструкция отката.
- Владелец разрешил публикацию.

## Модель работы Codex
После каждого выполненного задания сообщай: ветка, короткий SHA коммита, сделанное, реально запущенные проверки, результаты, оставшиеся проблемы. После существенной серии — PR для владельца. Сначала проверить, затем сохранять стабильную версию.
