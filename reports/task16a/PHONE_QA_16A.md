# №16-А — проверка с телефона

Компьютер, ручной перенос кода, пароль, client secret, clasp-авторизация и Google Drive scopes от клиента не требуются.

## Сначала одна APK для реальной авторизации

Сборка43037688974 SUCCESS; размер193711321байт, SHA256 `893a83cb06e9f5baf80643fac7946d9fdcf3ebdefbb3c948ff94415087d7fcd3`. Файл независимо скачан и проверен, endpoint/WebID прочитаны из APK, сертификат совпадает с прежним. В GitHub нужно войти своим обычным аккаунтом владельца. Это один тестовый кандидат, не финальная пара.

1. Установите мастерскую APK поверх прежней «Сульфи», не удаляя приложение. При конфликте пакета/подписи остановитесь и пришлите сообщение; удалять приложение/аудио нельзя.
2. «Дневник» → значок «Подключение и права» → «Войти через Google» → аккаунт владельца. Должно появиться «Мастер». Нажмите «Проверить права на сервере». Проверка создаёт и закрывает только собственную ограниченную техническую публикацию, не трогая личный контент. Пришлите результат без email/токенов.
3. Выйдите и войдите с ДРУГИМ Google-аккаунтом (либо установите тот же кандидат на второй телефон). Должно быть «Клиент». Та же проверка должна подтвердить запрет публикации; авторские редакторы недоступны, чтение опубликованного каталога доступно. Тип мастерской APK сам не даёт прав.
4. Под клиентом откройте «Библиотека → Облачный каталог», откройте опубликованный модуль/трек и установите в библиотеку. Подтвердите состав/количество и офлайн-проигрывание. Отдельно сообщите, что после выхода приватный авторский контент не виден.
5. После перезапуска авторские облачные функции требуют Google-входа заново: ID token не сохраняется в SQLite. Локальная библиотека и сессии остаются на устройстве.
6. Сообщите: MASTER-проверка / CLIENT-проверка / клиентский каталог и установка / ошибка либо успех / приблизительные секунды. Никакие токены не копируйте в чат. Серверный безопасный статус отдельно проверяется CI по приватным proof-записям.

Если Google блокирует второй аккаунт, пришлите точный текст/скрин сообщения (личные данные закройте) и безопасный код SDK, который показывает приложение. Клиентские email в test users не добавляем и не обходим OAuth. Решение о Google Testing/Production принимается только по фактическому ответу.

## После серверной проверки — две APK / два телефона

Будут собраны отдельные мастерская и клиентская APK с прежней подписью и увеличенным versionCode. До этого этап не засчитывается.

- Телефон1 / владелец: создать «Индукция Элмана» из 3 настоящих своих треков, опубликовать через карточку каталога. В редакторе дневника «Добавить из каталога» выбрать точный опубликованный модуль и опубликовать запись.
- Телефон2 / другой Google-аккаунт / клиентская APK: открыть дневник → карточку каталога → установить модуль. Проверить ровно 3 недостающих аудио, паузы/порядок/SHA-состав и отсутствие повторного скачивания уже имеющегося трека.
- Отключить сеть: воспроизвести все треки. Сделать личную изменённую копию модуля; оригинал и копия отдельны. Проверить локальный экспорт своей копии, без публикации в общий каталог.
- Перезапустить приложение, выйти/снова войти, проверить роли и невидимость чужих приватных данных. Снятие публикации останавливает новую установку, но не удаляет принятую офлайн-копию.
- Замерить отдельно: Google-вход, публикация, открытие каталога, установка 3 треков, запуск офлайн. Не использовать 51:42 прежнего CI как время установки.

Прежнее предупреждение shared=true уже разобрано: полный permissions ACL у Script owner-only. Менять доступ к серверному файлу или старому дневнику не требуется.
