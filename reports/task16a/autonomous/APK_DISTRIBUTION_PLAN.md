# №16 — бесплатная выдача APK24, без изменения доступа

## Проверено сейчас

GitHub API подтверждает: release 442038688 остаётся draft=true/prerelease=true. Два existing assets 736432720/736433144 имеют прежние размеры/SHA (см. APK24_DISTRIBUTION_MANIFEST.json). Anonymous GET страницы draft даёт HTTP404. В изолированном CI contents:read integration token получил HTTP403 при скачивании draft assets; transient job token с contents:write смог скачать все три существующие APK23/24 и проверить SHA. Это не изменение ACL и не публикация, GET-only step не пишет releases/данные. Доступ к draft рассчитан на владельца/редакторов; read-only и анонимный тестировщик не получают удобной ссылки.

Не приглашать тестировщиков в приватный source repository ради APK: это раскроет больше, чем нужно. Не передавать токены/пароли, временные signed redirect URL или .clasprc. Не публиковать текущий draft без разрешения.

## Уже доступный бесплатный способ

1. Владелец на Android входит в GitHub своим аккаунтом и открывает существующую страницу двух APK: https://github.com/luxhypnomaster/sulfi-hypnotherapy/releases/tag/untagged-9962b11f7ce0aa819785
2. Скачивает из Assets только sulfi-master-test-24.apk и sulfi-client-test-24.apk. Если открывается webview с другим аккаунтом, открыть ссылку в Chrome с нужной GitHub-сессией. Draft может быть недоступен обычному read-only collaborator.
3. Мастерскую APK установить поверх текущей «Сульфи». Клиентский файл передать второму телефону через Quick Share/Bluetooth/системное «Поделиться»; получателю не требуется GitHub-доступ. Google Drive не используется.
4. При конфликте установки не удалять приложение/данные. Зафиксировать точный текст ошибки и версию установленного приложения; сравнить package+certificate. APK24 не пересобирать с другим ключом.

Действия передачи должен выполнить человек, когда станет доступен. Сейчас они NOT_RUN. Эмуляторный upgrade не заменяет upgrade телефона владельца.

## Подготовленный вариант для независимых ссылок

После отдельного разрешения владельца можно создать отдельный бесплатный публичный binary-only GitHub repository без исходников/CI/secrets, с README для тестировщиков и двумя APK как release assets. Не открывать исходный repository и не публиковать его release. Взять только существующие проверенные APK, сверить manifest, не прикладывать user DB, аудио, keystore, .env или exports. Заголовок должен явно говорить «тестовая сборка, physical Google QA ещё не завершена»; не выдавать за принятую версию. Автоматизация публикации сейчас не создавалась и не запускалась.

Справка GitHub, прочитана 2026-11-11: https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases — до1000assets, каждый <2GiB, нет общего лимита размера релиза/bandwidth. Наши ~185MiB подходят. Это текущие опубликованные условия, не обещание неизменного тарифа. Публичный APK доступен любому; поэтому нужны согласование и проверка прав на ресурсы. Видимость приложения не предоставляет роль MASTER: её по-прежнему назначает сервер по настоящей Google identity.

Actions artifact storage сейчас исчерпан, поэтому upload-artifact может завершаться warning. Старые artifacts не удалялись. Release assets — другой механизм хранения; исчерпание artifacts не означает, что APK24 пропали. Никаких платных сервисов, новых ACL или публичных публикаций в этой работе не было.
