# Задание 14 — локальный перенос материалов

База: принятый №13 `64639bd627eb102781c69d78d9d8889b05646c2f`. Ветка `feat/task14-portable-content`. Главная ветка и принятый RunScreen/PlayerArt/assets не изменяются. Требования: [TASK_RU](../docs/task14/TASK_RU.md), [46 проверок](../docs/task14/ACCEPTANCE_MATRIX.md).

Реализованы возврат из истории на главную; семантическая индикация изменённых модулей/шаблона с Undo; выборочный ZIP трека/модуля/шаблона через прежний CapsuleService; добавочная SQLite v9 с append-only реестром снимков и происхождением личных копий; локальный каталог выбранного ZIP, точный resolver и реальная установка через проверенный importer; структурные локальные ContentLink дневника.

Это частичное выполнение архитектурной части D/E: предыдущие определения сохраняются, но существующий исполняемый аудио-ID ещё не является RevisionKey. Подмена байтов под прежним ID блокируется, новая версия не переключает историю на latest. Разные логические ID с одинаковым SHA занимают отдельные физические файлы из-за прежнего UNIQUE(filePath); ZIP дедуплицирован. Полный versioned blob-store с ref tracking/GC и выбором старой аудиоревизии требует следующей безопасной миграции; его наличие не заявляется. Legacy provenance остаётся неизвестным.

Каталог: Библиотека → настройки → «Локальный каталог материалов» → выбрать ZIP → карточка → установка. Каталог работает с реальными локальными пакетами; сервера и встроенных официальных демоматериалов нет. Исходный ZIP проверяется полностью при индексации; это локальный источник, не сетевое скачивание заголовков. Повторная установка не дублирует объекты. Конфликт другой ревизии отменяется, не перезаписывается молча.

Экспорт: меню трека/модуля/шаблона → «Экспорт …». Сохранить ZIP системным диалогом. Импортировать можно прежней страницей резервных копий или выборочно каталогом. Частный дневник и история не входят в выборочный экспорт. Капсулы databaseSchema 6/7/8 принимаются новым приложением; новые пакеты 9 не обещаны старым APK.

ContentLink хранится в локальном DiaryEntry.extra.contentLinks и содержит type, logicalId, revision, digest, action. Неизвестные поля сохраняются локально. Установленный материал открывается существующим preview/каталогом; отсутствующий требует точного локального пакета. Ссылка не выдаёт прав доступа. Выгрузка/публикация записи с новым полем заблокирована до подтверждения серверного контракта; live Apps Script не изменён. UI добавления ссылки автором в этом этапе не создан: путь чтения работает для записей, действительно содержащих ContentLink.

Проверки: целевые capsule/resolver/migration/semantic/navigation/widget tests, полная Flutter-регрессия, analyze/format, отдельный CLIENT, Node и штатный GitHub CI. Подробные результаты, актуальный SHA, APK и настоящие Flutter-скриншоты сохраняются в [Отчёты — Задание 14](https://drive.google.com/drive/folders/1SAIk6swRXXHa07MDH10irzoiDKPYgkAT). Статусы следует смотреть в TESTS.md, не считать этот перечень физической проверкой.

Android вручную: предварительно создать внешнюю капсулу; установить совместимо подписанный APK поверх текущего без удаления; проверить 4 личных аудио, шаблоны, историю и дневник; изменить/отменить порядок внутри модуля; выгрузить шаблон и перенести на отдельную тестовую установку; проверить звук/фон/звонок/SAF. Физическое устройство не подключено. Package ID, version 0.4.12+17 и закреплённый сертификат не меняются. APK публикуется штатным CI на GitHub, не на Google Диск.

Откат: старый APK может отказаться от SQLite v9; downgrade без потери не обещается. Предпочтителен исправляющий APK с поддержкой v9 и прежней подписью. Ни удаление приложения, ни сброс данных не являются способом отката. Снимки Git/APK не заменяют резервную капсулу.
