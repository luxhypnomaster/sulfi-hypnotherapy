# №24 — остаток, ограничения, безопасная интеграция

## Что не объявляется завершённым

- APK/AAB, Gradle/native build, эмулятор, реальные телефоны, Android gesture/notification и настоящие Google-пользователи: **DEFERRED_BY_OWNER / NOT_RUN**. Flutter `handlePopRoute` проверяет Navigator, а не физический Android Back. Native notification-path проверен по общему UI opener в исходнике, не на устройстве.
- Production GAS/OAuth/ACL/signing/main и данные пользователя не изменены. Готовность приложения к релизу не заявляется.
- Родительские PR51/52/54/55 не объединены. Статус №23 остаётся PARTIAL17/1/2, его неизвестная причина старого owner-инцидента и отложенные нативные проверки не «закрываются» заданием24.
- Stage21/22 capabilities/defaultOFF и их live/server blockers остаются прежними. UX-проверки не заменяют их интеграцию.

## Конкретные границы

Переключение публикаций разрешает только текущие видимые IDs; это не новая система прав и не обход проверки API. Корневой reader без реального Home маршрута возвращается к существующему журналу. Home fallback создаёт реальный HomeScreen только из имеющегося SessionScope. Для viewer с уже существующим родителем Back его сохраняет.

Удаляется лишь добавленный дубликат опубликованного readonly-reader того же DiaryController/scope/id/контекста. Редакторы, preview/review, диалоги и маршруты других публикаций не удаляются. Очередь не раскрывается через принудительный popUntil поверх несохранённого диалога. Эти границы покрыты адресными тестами; сложные Android deep-link/intent сценарии остаются будущей приёмкой.

## Проверки и затраты

Первый предварительный full-run остановлен после обнаружения конкретной недостающей передачи фильтра журнала. Изолированный RED на предыдущем коде подтвердил post2 вместо ожидаемого post10. Короткий преждевременный run остановлен перед заморозкой из-за трёх style-info анализатора. Оба лога не считаются PASS. После исправлений и чистого анализатора запущен окончательный полный suite на зафиксированном source; точные результаты — TESTS.md. Никаких повторов Gradle/эмулятора/CI и попыток исправлять billing.

Первый MASTER queue screenshot был снят до декодирования декоративного bitmap в синтетическом холодном harness. Он исключён из визуальных доказательств. Сохранён корректно декодированный общий queue-render CLIENT, рендеры обоих Home/щитов и отдельные тесты обоих изданий. Это ограничение capture, не смена оформления MASTER.
