# №16-В — безопасная диагностика, без действий на телефоне

Состояние владельца: `MISSING_FROM_UI_AFTER_STANDARD_UPDATE; PHYSICAL_BYTES_UNKNOWN`.
Наличие старых APK или серверного каталога не доказывает сохранность личной базы.
Никаких запросов uninstall/clear/cache/downgrade/import/logout/relogin, установки диагностической APK или ADB владельцу не выдано.

## Что реально доступно

- Точные APK24/25: GitHub private draft GET + SHA, native apksigner verify и aapt package/version.
- Точный diff source24→25; неизменные storage/model/Android/lockfile blobs.
- Disposable Android35/KVM в CI: можно создавать тестовые материалы через UI APK24 и читать только собственный sandbox.
- Физическая SQLite/медиа владельца: доступа нет, их состояние UNKNOWN.
- APK24/25 — debug-варианты, но успешный run-as в эмуляторе не означает доступ к телефону. ADB с телефона/веб-ADB не обещается.

## Инструмент анализа КОПИИ

`scripts/task16v/readonly_inventory.py <directory>` принимает УЖЕ полученную согласованную forensic-копию директории files с `library.sqlite`, при наличии `library.sqlite-wal`, `library.sqlite-shm`, `audio/`.
Сам копии с телефона не получает. Исходник открывает только на чтение; SQLite открывает временный дубликат mode=ro, WAL и SHM сохраняет вместе. Не выполняет checkpoint/VACUUM/migration/GC/recovery. Отсутствующая база не создаётся. Проверяет, что исходные DB/WAL/SHM байты не изменились во время анализа. Результат редактирован: hashes/counts/integrity, без названий, текстов, токенов и subjects.

Неполная/нестабильная копия не является доказательством отсутствия данных. Консистентность приобретения оригинала должна быть доказана отдельно: это не автоматическая инструкция владельцу. Копировать только .sqlite без WAL нельзя считать полным forensic-снимком. Никакого `immutable=1`, игнорирующего WAL.
