# №16-В — план сохранения и восстановления существующих материалов

**Сейчас: BLOCKED, новые действия с телефоном не требуются.** Подтверждён обычный Android update24→25 без удаления. Существующие bytes владельца UNKNOWN. Ни APK26, ни диагностическую установку на единственный телефон не предлагаем.

1. Сохранить текущее состояние. Не удалять/переустанавливать приложение, не чистить cache/storage, не откатывать24, не выполнять logout/account switch, импорт/повторный импорт, создание заменяющих одноимённых материалов, GC или сброс. Уже существующие внешние ZIP-капсулы просто сохранить; сейчас их не импортировать.
2. Мы выполняем read-only аудит точных APK/source и controlled native тесты. Внутренние файлы владельца не получали, не открывали и не меняли. Одновременное отсутствие tracks/modules/drafts пока не объяснено.
3. Если controlled native сценарий не воспроизводит полный инцидент, следующий шаг участия владельца — только согласованные сведения с экрана (версия/вид пустого списка/активный раздел без содержимого личных записей). Это не просьба повторить вход или переустановить приложение. Никаких токенов, паролей и личных аудио в чат.
4. Получение полного forensic snapshot `SQLite+WAL/SHM+media tree` с release/debug Android должно иметь технически проверенный способ и отдельное согласие владельца. Рабочего phone-only способа сейчас не доказано. `run-as` на CI эмуляторе не доказывает его доступность на телефоне. До приобретения согласованной полной неизменной копии не запускать recovery writes.
5. По копии определить состояние. Если rows+bytes присутствуют — проверять пути/читатель/фильтр; не перемещать и не перезаписывать media, не менять ID и module graph. Для legacy diary scope уже подготовлен только source patch: точный server-verified owner alias, без миграции. Но он не объясняет missing tracks/modules и не является разрешением обновления телефона.
6. Если потребуется миграция: read-only inventory → полная snapshot с проверенным SHA/размером → staging/atomic transition → exact IDs/graph/block-order/hash readback → rollback bytes из сохранённого snapshot при сбое. Такой migration code сейчас не нужен для alias и не добавлен.
7. Если bytes реально отсутствуют, сначала доказать это на полной копии. Источники восстановления могут быть только конкретная имеющаяся внешняя капсула, подтверждённая OS/App backup, исходный импортный файл. Наличие любой из них у владельца не предполагаем. Серверный каталог не backup всех записей/черновиков; голос, записанный только в app, нельзя воссоздать из APK/Git.
8. APK26 допустима только после полного RCA, native UI-created preserved dataset, независимой проверки безопасности/снимка и review, затем отдельного согласования обновления владельцем. Сейчас условия не выполнены. Автоматической установки не будет.

Дополнение бинарного аудита: в обеих APK запрещены Android auto-backup/fullBackupContent и cloud/device extraction. Стандартная Google OS-копия не предполагается и не обещается; существование какого-либо внешнего/OEM архива нужно доказать отдельно.
