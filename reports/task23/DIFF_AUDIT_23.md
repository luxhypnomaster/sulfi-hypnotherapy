## Новое воспроизведение на проверенной базе PR54

`logs/repro-red.log`: исходные четыре теста исполнились, 0 PASS / 4 FAIL с конкретными assertions (не ошибка компиляции). После узких исправлений `logs/repro-green.log`: 4 PASS. Кодовые причины:

1. Фоновое открытие несуществующей базы: onCreate-отказ слишком поздний; новый пустой SQLite уже лежит на диске. Исправлено ранним no-create/preflight version gate.
2. Имя файла/папки считалось достаточным доказательством права удалить капсулу при старте. Исправлено сохранением неопределённых байтов на месте.
3. Inspect и restore использовали один изменяемый Map. Проверенный hash больше не гарантировал состав импортируемых записей. Исправлено привязкой digest + глубоким снимком + повторной проверкой перед commit.
4. Роль MASTER считалась правом на все приватные черновики в таблице. Исправлено использованием существующего точного scope-check без изменения OAuth.

Дополнительные отрицательные сценарии: wrong-path SQLite alias, старый schema в headless worker, изменение состава на beforeCommit, изменение медиа после alreadyImported, смена scope в процессе ZIP, missing media. Во всех отказах проверяются отсутствие частичных строк и сохранность прежних байтов.

## Что намеренно не менялось

Нет новой schema/DDL, удаления legacy documents, автоматического выбора/слияния нескольких баз по названию/email, автоматической переклейки audio logical ID на новые байты. Полное сосуществование аудиоревизий — отдельная ранее известная задача, а не повод переписать библиотеку здесь. SQLite при коррупции не заменяется пустой БД. Неизвестные файлы не считаются мусором. Исторический owner-инцидент не объявлен физически воспроизведённым.
